## UI Patterns & Component Inventory

### Per-Band Setlist List Screen (`SetlistListScreen`)

**Focal Point:** Ordered list of setlists with track count and duration; FAB for quick create action.

**Pattern:** Cache-first async list with FAB for create (mirrors Phase 3 Tracks).

**Layout:**
- AppBar with title "Setlists"
- Body: ListView.separated
  - Empty state (if no setlists): centered heading + body + action button
  - Populated list: ListTile per setlist row
- FAB: add setlist icon, tooltip "Add setlist"

**Row item contents:**
- Title: Setlist name
- Subtitle: Event location (if set) or date (if set)
- Trailing: Track count + duration (e.g., "8 tracks, 42m 35s")
- Secondary info: Event date below location (if set), or "No date set" placeholder
- Tap action: Navigate to SetlistDetailScreen

**State coverage:**
- Empty: "No setlists yet" heading + body + "Add setlist" button
- Loading: Center CircularProgressIndicator
- Error: Error widget with "Tap to retry" action (ref.invalidate pattern)
- Populated: ListView with ListTile rows

### Setlist Detail Screen (`SetlistDetailScreen`)

**Focal Point:** Ordered track list with server-computed duration; toggleable edit mode reveals drag handles and remove icons.

**Pattern:** Read-only detail with edit icon + toggleable edit mode for reordering/adding/removing tracks.

**Layout:**
- AppBar: Setlist name as title, edit icon button (top-right)
- Body: ListView with sections
  - Header: Setlist name (large), location (if set), date (if set), duration
  - Track list: Ordered list of tracks, one per row
    - Normal mode (read-only): Title + artist + duration per track
    - Edit mode: Each row gains a drag handle + remove icon
- FAB: Only in edit mode, "Add tracks" button

**Edit Mode Toggle:**
- In normal view, show "Edit" TextButton in AppBar action area (or as a button below header)
- In edit mode, show "Done" TextButton to exit
- Edit mode hides on screen pop (user presses back or Done)

**Track Row Contents (Edit Mode):**
- Drag handle icon (ReorderableDragStartListener wrap)
- Track title + artist
- Track duration
- Remove icon (X or trash, red/error color)

**State coverage:**
- Empty tracks: "No tracks in this setlist" message
- Loading: CircularProgressIndicator
- Error: Error widget with retry action
- Populated: ListView with track rows + edit mode toggle

### Create Setlist Form (`CreateSetlistScreen`)

**Focal Point:** Multi-select track checklist below name/location/date fields; creates setlist with optional initial tracks in one submission.

**Pattern:** Full-screen form, ConsumerStatefulWidget with Form validation.

**Layout:**
- AppBar: "Create setlist" title, no actions
- Body: ListView inside Form
  - Name field (TextFormField, required)
  - Location field (TextFormField, optional)
  - Date field (TextFormField, optional, hint "YYYY-MM-DD")
  - Multi-select checklist section: "Add tracks (optional)" heading
  - CheckboxListTile per available track (title + artist)
  - Buttons: "Create" (ElevatedButton) + "Cancel" (TextButton)

**Form validation:**
- Name: non-empty (validator: "Name is required")
- Location: no validation (optional)
- Date: if provided, validate ISO 8601 format (optional validator)
- Tracks: no validation (0 to 100 tracks accepted)

**Success:** Navigate to SetlistDetailScreen(bandId, newSetlistId)
**Error:** Show snackbar with error message, keep form open

**Spacing:**
- Form padding: lg (24px) all sides
- Between fields: md (16px)
- Checkbox list padding: lg top margin

### Edit Setlist Form (`EditSetlistScreen`)

**Focal Point:** Name/location/date fields pre-filled with current values; all fields always sent on submit (including explicit `null` for cleared fields).

**Pattern:** Full-screen form (mirrors create, minus track picker).

**Layout:**
- AppBar: "Edit setlist" title
- Body: ListView inside Form
  - Name field (TextFormField, required, pre-filled with current value)
  - Location field (TextFormField, optional, pre-filled)
  - Date field (TextFormField, optional, pre-filled)
  - Buttons: "Save" (ElevatedButton) + "Cancel" (TextButton)

**Form behavior:**
- Always send all editable fields on submit, including explicit `null` for cleared fields (Phase 3 CR-02 pattern)
- Show snackbar on error
- Navigate back to detail screen on success (which will show updated values)

### Delete Setlist Dialog (`ConfirmDeleteSetlistDialog`)

**Focal Point:** Simple warning text with destructive confirm button; minimal friction for irreversible action.

**Pattern:** Lightweight cancel/confirm dialog (Phase 3 precedent).

**Layout:**
- Title: "Delete setlist?"
- Body: "This action cannot be undone."
- Actions: "Cancel" (TextButton) + "Delete" (TextButton with error color)

**Behavior:**
- Show on user tap of delete action (triggered from detail screen)
- On confirm: Call API, show snackbar, navigate back to band's SetlistListScreen
- On cancel: Dismiss dialog

### Add Tracks Dialog (`AddSetlistTracksDialog`)

**Focal Point:** Multi-select checklist of band's available (not-already-added) tracks; checkbox state per track with title/artist/duration visible.

**Pattern:** Multi-select checklist picker, submits via bulk endpoint.

**Layout:**
- Title: "Add tracks"
- Body: ListView of CheckboxListTile
  - Item: Track title + artist + duration
  - Checkbox state: pre-selected if already in setlist (disabled, grayed out)
  - Tap to toggle selection
- Empty state: "No more tracks available" if all tracks already in setlist
- Actions: "Add" (ElevatedButton) + "Cancel" (TextButton)

**Behavior:**
- Show selected trackIds in call to `addSetlistTracks()` (bulk endpoint)
- On success: Append to detail's track list, close dialog
- On error: Show snackbar, keep dialog open

**Limits:** Max 100 trackIds (API constraint, implicit in form submission)

### Global Setlists Tab (`SetlistsScreen`)

**Focal Point:** Flat cross-band setlist list with band-name badge per row; filter dropdown (top-right) narrows to single band or shows all.

**Pattern:** Cross-band flat list with band-name badge + band filter (mirrors Phase 3 Tracks tab).

**Layout:**
- AppBar: "Setlists" title, filter dropdown in action area (right side)
- Filter dropdown: "All bands" or selected band name
  - Opens dropdown menu: "All bands" + one menu item per band (sorted by name)
- Body: ListView.separated
  - Empty state: "No setlists" heading + body
  - Populated: ListTile per setlist
    - Title: Setlist name
    - Subtitle: Band name (as badge or inline text)
    - Trailing: Track count + duration (same as per-band list)
    - Tap: Navigate to SetlistDetailScreen (with bandId context)

**Filter state:**
- Watched via SelectedBandIdFilter notifier (Riverpod)
- Filter dropdown shows current selection
- Changing filter triggers UserSetlistsListData rebuild

**State coverage:**
- Empty (all bands): "No setlists" message
- Empty (filtered band): "No setlists in {Band Name}" message
- Loading: CircularProgressIndicator
- Error: Error widget with retry action

## Assumptions to Confirm

1. **Drag-and-drop package:** RESEARCH.md recommends `reorderable_grid_view` or `flutter_reorderable_list`, but exact choice deferred to spike. Phase 1 execution must finalize selection.
   - Risk if wrong: Requires package swap mid-phase if chosen library doesn't support edit-mode toggle or has poor gesture handling.
   - Mitigation: 1-hour spike testing both libraries' ListView reordering before Wave 1.

2. **Reorder error handling:** D-14 specifies "immediately on each drop," but doesn't detail error recovery. UI-SPEC assumes revert-on-error + snackbar (Phase 3 delete pattern), but product may expect different UX.
   - Risk if wrong: User sees reordered tracks on screen, but server has old order if network fails.
   - Mitigation: Confirm revert-on-error behavior with product before execution.

3. **Icon for Setlists tab:** Assumes Material Icons has suitable icon (e.g., `Icons.setlist` or `Icons.music_note` reused). If not available, nearest icon chosen.

4. **Max tracks limit:** API schema specifies 100-item max for trackIds, implicit in form. No client-side picker limit enforcement (assumes all bands have <100 tracks).
