## Resolved Conflicts (RESEARCH.md / UI-SPEC.md vs. verified reality)

1. **`intl` version.** 12-RESEARCH.md and 12-UI-SPEC.md both suggest `intl: ^0.19.0+`. The installed Flutter SDK's own `flutter_localizations` package pins `intl: 0.20.2` exactly (verified: `packages/flutter_localizations/pubspec.yaml` in the local Flutter SDK checkout, and `intl-0.20.2` already present in `~/.pub-cache/hosted/pub.dev/`). Dart's caret syntax on a `0.x` version constrains to the same minor (`^0.19.0` == `>=0.19.0 <0.20.0`), which would conflict with the SDK's exact `0.20.2` pin and fail `flutter pub get`. This plan uses `intl: ^0.20.2` instead.
2. **AppBar title localization.** 12-UI-SPEC.md's own ARB Seed Strings table, D-07 (12-CONTEXT.md), and Pattern 3's code example all include `appBarSettingsTitle` as an ARB-backed string — but 12-UI-SPEC.md's "Localization Testing Strategy" and "Known Limitations" prose sections separately (and inconsistently) describe the AppBar title as staying hardoded until Phase 13. D-07 is a locked user decision and takes precedence over the inconsistent prose; this plan localizes the AppBar title via `appBarSettingsTitle`, matching the ARB table and Pattern 3.
3. **`RadioListTile<Locale>` wiring.** 12-RESEARCH.md's Pattern 3 and 12-PATTERNS.md's illustrative code both set `groupValue`/`onChanged` directly on each `RadioListTile<Locale>`. Both parameters are `@Deprecated` in the installed Flutter SDK (3.44.9; confirmed in `packages/flutter/lib/src/material/radio_list_tile.dart`: `'Use a RadioGroup ancestor to manage group value instead'`). This plan wraps the two Language tiles in their own nested `RadioGroup<Locale>` instead, matching how the existing `ThemeMode` tiles already rely on an ambient `RadioGroup<ThemeMode>` with no per-tile `groupValue`/`onChanged`.
4. **UI-SPEC's "backstop/manual" framing for E3/E4.** 12-UI-SPEC.md's UI Considerations section defers background-tab propagation (E3) and persistence/logout-survival (E4) to Phase 13 manual tests. Since ROADMAP.md's Phase 12 success criterion 5 explicitly requires background-tab propagation as *this* phase's own deliverable, and the underlying mechanism (`Localizations.localeOf(context)`, a second `ProviderScope` pump, SharedPreferences read-back) is testable today without Phase 13's string sweep, this plan elevates both to automated, explicit-verification tests rather than deferred manual checks.
