### Locale Propagation

**LocaleController** (New, `lib/providers/locale_provider.dart`)

Mirrors `ThemeController` pattern exactly:

```dart
import 'package:flutter/material.dart';
import 'package:riverpod_annotation/riverpod_annotation.dart';
import 'package:shared_preferences/shared_preferences.dart';

part 'locale_provider.g.dart';

@riverpod
class LocaleController extends _$LocaleController {
  static const String _localeKey = 'app_locale';
  
  @override
  Future<Locale> build() async {
    final prefs = await SharedPreferences.getInstance();
    final languageCode = prefs.getString(_localeKey) ?? 'en';
    return Locale(languageCode);
  }

  Future<void> setLocale(Locale locale) async {
    state = AsyncData(locale);
    final prefs = await SharedPreferences.getInstance();
    await prefs.setString(_localeKey, locale.languageCode);
  }
}
```

**Persistence:** `shared_preferences` package (D-03) — stores `'app_locale'` key with language code (`'en'` or `'ru'`).

**Lifecycle:**
1. App startup: `LocaleController.build()` reads from SharedPreferences, defaults to `Locale('en')` if not set
2. User selects language: `setLocale()` updates state + persists to SharedPreferences
3. App restart: Reads persisted value, restores selected language (no API call)
4. Logout (signOut): SharedPreferences language key is NOT cleared (D-04) — language is a device preference, not account data

**Important:** `AuthSession.signOut()` must NOT be modified to clear SharedPreferences. Explicitly document in code comments that language preference survives logout per D-04.

### Material App Integration

**File:** `lib/app.dart`

**Changes to CadenceApp:**

```dart
import 'package:flutter/material.dart';
import 'package:flutter_localizations/flutter_localizations.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';

import 'features/auth/auth_gate.dart';
import 'generated/app_localizations.dart';  // Generated by gen-l10n
import 'navigation/root_scaffold.dart';
import 'providers/locale_provider.dart';    // New import
import 'providers/theme_provider.dart';
import 'theme/app_theme.dart';

class CadenceApp extends ConsumerWidget {
  const CadenceApp({super.key});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final themeMode = ref.watch(themeControllerProvider);
    final locale = ref.watch(localeControllerProvider);

    return locale.when(
      data: (selectedLocale) => MaterialApp(
        title: 'Cadence',
        debugShowCheckedModeBanner: false,
        theme: AppTheme.light,
        darkTheme: AppTheme.dark,
        themeMode: themeMode,
        
        // Localization bindings
        localizationsDelegates: [
          AppLocalizations.delegate,
          GlobalMaterialLocalizations.delegate,
          GlobalWidgetsLocalizations.delegate,
          GlobalCupertinoLocalizations.delegate,
        ],
        supportedLocales: const [
          Locale('en'),
          Locale('ru'),
        ],
        locale: selectedLocale,
        
        home: AuthGate(builder: (context) => const RootScaffold()),
      ),
      loading: () => MaterialApp(
        title: 'Cadence',
        home: Scaffold(
          body: Center(
            child: CircularProgressIndicator(),
          ),
        ),
      ),
      error: (error, stack) => MaterialApp(
        title: 'Cadence',
        home: Scaffold(
          body: Center(
            child: Text('Error initializing app: $error'),
          ),
        ),
      ),
    );
  }
}
```

**Key Points:**
- Watch `localeControllerProvider` and bind to `MaterialApp.locale`
- Add `localizationsDelegates` for Material + Cupertino localizations
- List `supportedLocales` as `[Locale('en'), Locale('ru')]`
- Wrap body in `.when()` to handle async loading of persisted locale
- Theme watcher remains unchanged

## State Contract

**Loading State (on app startup):**
- While locale preference loads from SharedPreferences: Show circular progress indicator (fallback loading UI in CadenceApp)
- Duration: <200ms on typical devices (SharedPreferences is local)
- Once loaded: Replace with normal app UI with selected locale

**Active Selection State:**
- RadioListTile shows filled radio button for currently selected locale
- Tapping a different radio button triggers state change immediately
- Locale change propagates via Riverpod to `MaterialApp.locale`

**Live Update Contract:**
- Selecting a language change in Settings
- All visible text in current screen updates immediately (via AppLocalizations in MaterialApp rebuild)
- Text in inactive `IndexedStack` tabs (e.g., Bands tab not currently visible) updates on next navigation to that tab
- No app restart required; no navigation stack reset required
- Dialog/overlay text also updates if visible at moment of selection

**Persistence Contract:**
- After selection and app close, reopening app in 10 seconds → same locale
- After selection, logout, and login as different user → login screen still shows selected language (device pref)
- After device reset or SharedPreferences cleared (cache clear via OS settings) → defaults to English

## Localization Testing Strategy

**Proof of Success (Requirement I18N-01, I18N-02, I18N-03):**

1. **Manual test: Language switch applies live**
   - Open Settings
   - Tap "Русский"
   - Verify "Язык" header text updates immediately (no restart)
   - Verify "Тема" header also updates to "Тема" (from "Theme")
   - Radio button stays selected on "Русский"

2. **Manual test: Settings AppBar updates**
   - From Theme selection, AppBar title "Settings" remains "Settings" (not yet in ARB, Phase 13 will handle app-wide)
   - Switch language again to English
   - AppBar still shows "Settings" (expected — not yet localized)

3. **Manual test: Persistence across restart**
   - Select "Русский" in Settings
   - Close app completely (not backgrounded)
   - Reopen app
   - Verify app opens in Russian (Language header shows "Язык", Theme header shows "Тема")
   - Go to Settings, verify "Русский" is selected

4. **Manual test: Background tab propagation**
   - With app in English, navigate to Bands tab
   - Return to Profile tab (where Settings can be accessed)
   - Open Settings, switch to "Русский"
   - Tap back to Bands tab
   - Next phase (Phase 13) will add strings to Bands; verify those render in Russian when you navigate there after language switch (Phase 12 responsibility: Localizations framework handles this, no special code needed; backstop test in Phase 13)

5. **Manual test: Logout preserves language**
   - Select "Русский" in Settings
   - Log out from Profile
   - Login screen appears in Russian (language header "Язык" would be visible if Settings screen were reachable before login — not applicable here; backstop: Phase 13 localizes login screen, Phase 12 just ensures persistence survives logout)
   - Log back in
   - App reopens in Russian

## Edge Cases & Backstop Tests

| Case | Current Phase | Backstop / Notes |
|------|---------------|------------------|
| Device locale is Russian, but app has no user preference saved | ✅ Phase 12 | Defaults to English per D-05 (no auto-detect; is deterministic) |
| User selects language while phone theme-switches (e.g., sunset auto-switch to dark) | ✅ Phase 12 | Theme and locale are independent Riverpod providers; both update independently via separate watchers in CadenceApp |
| User selects language while offline | ✅ Phase 12 | SharedPreferences is local; no network call needed; persists immediately |
| SharedPreferences somehow returns a locale string not in supportedLocales (e.g. `'fr'`) | 🧪 Phase 13+ | Phase 12 guarantees only 'en' or 'ru' are written via setLocale(); phase-12-era defensive code: if build() reads an unexpected value (shouldn't happen), default to Locale('en') in catch block |
| User rapidly taps language options (System -> Light -> Dark -> back to System in Theme, or English -> Russian -> English) | ✅ Phase 12 | RadioGroup enforces single selection; rapid taps just re-set the same value, no queuing or debounce needed |
| App backgrounded while in Settings, system kills process, app reopened from process death (not warm restart) | ✅ Phase 12 | SharedPreferences persists to disk; process death doesn't affect it; app reopens with saved locale |
