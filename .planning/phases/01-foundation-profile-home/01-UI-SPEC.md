## Color

Material Design 3 dynamic theming via `ColorScheme.fromSeed`.

**Light Theme:**

| Role | Seed | Primary | Surface | OnSurface | Description |
|------|------|---------|---------|-----------|-------------|
| Dominant (60%) | `Colors.deepPurple` | Deep Purple | White/light gray | Dark gray/black | Backgrounds, surfaces, app chrome |
| Secondary (30%) | Auto-derived from seed | Teal/purple tones | Card surfaces, sidebar backgrounds | Contrast text | Cards, elevated surfaces, navigation |
| Accent (10%) | Auto-derived (primary) | Deep Purple/teal | Interactive elements | Contrast text | Primary buttons, links, active states only |
| Destructive | Red (Material 3 error) | `Color(0xFFB3261E)` | Error surfaces | White/light text | Delete/logout actions, destructive confirmations only |

**Dark Theme:**

| Role | Seed | Primary | Surface | OnSurface | Description |
|------|------|---------|---------|-----------|-------------|
| Dominant (60%) | `Colors.green` | Green | Dark charcoal/near-black | Light gray/white | Backgrounds, surfaces, app chrome |
| Secondary (30%) | Auto-derived from seed | Mint/green tones | Card surfaces (darker), sidebar backgrounds | Contrast text | Cards, elevated surfaces, navigation |
| Accent (10%) | Auto-derived (primary) | Green/mint | Interactive elements | Contrast text | Primary buttons, links, active states only |
| Destructive | Red (Material 3 error) | `Color(0xFFB3261E)` | Error surfaces | White/light text | Delete/logout actions, destructive confirmations only |

**Accent Reserved For:**
- Primary action buttons ("Save", "Create Band")
- Link text and navigation active states
- Selected tab indicators
- Form field focus/validation borders
- Loading spinners

Never use accent for secondary actions, disabled states, or informational text.

**Semantic Colors (Material 3):**
- **Success:** Green (auto-derived, primary in dark theme)
- **Warning:** Orange/amber (auto-derived tertiary in light theme)
- **Error:** Red (Material 3 error token, `Color(0xFFB3261E)`)
- **Info:** Blue (auto-derived secondary in light theme)

**Implementation:** Use `Theme.of(context).colorScheme` for all color references. No hardcoded hex values except error red (Material 3 standard).

**Source:** Pre-populated from `lib/theme/app_theme.dart` (light: `Colors.deepPurple`, dark: `Colors.green`) + Flutter Material 3 ColorScheme.fromSeed dynamics. Confirmed by codebase scan.

## Copywriting Contract

**Profile Screen (USER-01: "User can view own profile info via GET /api/me"):**

| Element | Copy |
|---------|------|
| Screen title | "Profile" |
| Label: Username | "Username" |
| Label: User ID | "ID" (if displayed; often internal only) |
| Refresh action | "Refresh" or refresh icon button |
| No data (error state) | **Heading:** "Couldn't load profile" **Body:** "Please check your connection and try again." [Retry button] |
| Empty/no username | (API contract guarantees username is required; treat as error) |

**Home Screen (USER-02: "User can view homepage summary (username, bands count) on app home tab via GET /api/homepage"):**

| Element | Copy |
|---------|------|
| Screen title | "Home" |
| Welcome message | "Welcome, [username]" (dynamic) |
| Bands count label | "Your bands" |
| Bands count display | "[N] band" or "[N] bands" (pluralize) |
| Empty state (zero bands) | **Heading:** "No bands yet" **Body:** "Create or join a band to get started. Tap the '+' icon to create one or ask a bandmate for an invite code." [Create Button] |
| No data (error state) | **Heading:** "Couldn't load home" **Body:** "Please check your connection and try again." [Retry button] |
| Refresh action | "Refresh" or refresh icon button |

**Cache-First Loading (Phase 1 behavior, no explicit copy, silent):**
- On screen load, show cached data immediately if available (no "Loading..." spinner).
- Fire background refresh silently; update in place when new data arrives.
- No "last synced" indicator (deferred to Phase 5 per roadmap OFFL-03).

**First Load (No Cache Yet) While Offline:**
- Show error state copy above with retry action.
- No fallback to empty placeholder — user must retry when connectivity restored.

**Destructive Actions in Phase 1:**
- None defined. Logout is in AuthGate (out of this phase's scope).

## UI Considerations & Assumptions

**Cache-First Loading Pattern (D-04):**
- On screen load: show cached data immediately if available (zero delay).
- Background refresh fires in parallel; replaces cache + re-renders when new data arrives.
- User sees no spinner or "loading" state on cache-hit.
- **Verification:** Manual test — load Profile/Home screen with cached data, observe immediate display, then verify refresh completes silently.

**Staleness Indicator Deferred (D-05):**
- Phase 1 does NOT display "last synced Xm ago" or any visual staleness cue.
- Cached data shown as-is; user cannot distinguish fresh from stale by visual inspection.
- Phase 5 adds staleness UI as a single cross-screen pass (profile, bands, tracks, setlists together).
- **Implication:** Phase 1 ships cache-first silently. Phase 5 owners must retrofit staleness indicators on the same screens.

**Silent In-Place Refresh (D-06):**
- When background refresh completes with data differing from cache, Riverpod provider state updates.
- Screen re-renders automatically (normal Riverpod reactive rebuild).
- No animation, transition, or "data updated" toast required.
- **Verification:** Manual test — edit cached data, trigger refresh, observe silent rebuild.

**No Offline Mutation Queue (Project Constraint):**
- Phase 1 is read-only cache only.
- Create/update/delete actions (landing in Phase 2+) require connectivity; are blocked offline.
- Phase 5 may surface mutation-blocking UI; Phase 1 does not.
