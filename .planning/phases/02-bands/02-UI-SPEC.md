## Color

**Primary Palette (Material 3 green seed):**

| Role | Usage | Notes |
|------|-------|-------|
| Primary | CTA buttons (Create Band, Join Band, Confirm actions), active icons, selected states | Green, generated from ColorScheme.fromSeed(seedColor: Colors.green) |
| Secondary | Secondary buttons, card backgrounds, inactive/secondary UI elements | Material-generated secondary from theme |
| Tertiary | Accent elements, focus states, secondary highlights | Material-generated tertiary from theme |
| Surface | Screen background, list backgrounds | Material light/dark surface color |
| Error | Destructive actions only (Delete Band, Leave Band, Remove Member), error messages | Material red (error) |

**60/30/10 Split:**

- **60% Dominant Surface:** Page backgrounds, card surfaces, list backgrounds (white in light, surface in dark)
- **30% Secondary:** Card containers, section dividers, inactive states (Material's secondary/tertiary generated colors)
- **10% Accent:** Primary CTA buttons (Create, Join, Confirm), success states — reserved explicitly for user-initiated creation and safe confirmations only

**Accent Reserved For:**
- Primary CTA: "Create Band" FAB and button
- Primary CTA: "Join Band" dialog submit
- Safe confirmation: "Join" button in join dialog
- Active/focused states in forms
- Material-generated interactive focus rings

**NOT used for:**
- Secondary/tertiary buttons (use Material's outline or text styles)
- Navigation state (handled by Material's BottomNavigationBar)
- Success messaging (inline text only, no color highlighting for this phase)

**Destructive Color (Error Red):**
- "Delete Band" button background or outline (red/error color from theme)
- "Leave Band" text/outline (red)
- "Remove Member" text/outline (red)
- Error message text in dialogs or error states
- Confirmation text: e.g., "Type [band name] to confirm deletion"

**Source:** Phase 1 app_theme.dart establishes green seed; existing profile_screen.dart uses ElevatedButton (primary), icon colors (primary), and Material's standard patterns.

## Styling Patterns & Constraints

### Bands List Screen

- **Layout:** Scaffold with AppBar ("Bands" title) + ListView.separated for band list + FAB
- **List item:** Material ListTile with leading BandAvatar (initial), title (band name, bodyLarge), trailing chevron, onTap → band detail screen
- **Spacing:** 16px item padding (Material ListTile default), 8px divider height (consistent with Phase 1)
- **Empty state:** Centered column with heading (headlineMedium), body (bodyMedium), and "Create Band" button (all 24px padding, lg spacing) — mirrors Phase 1 home_screen.dart pattern
- **Loading state:** Material CircularProgressIndicator centered (cache-first: only shown on first fetch or cache miss)
- **Error state:** Centered column with heading (headlineMedium), body, "Retry" button — matches Phase 1

### Band Detail Screen

- **Layout:** Scaffold with AppBar (band name as title, no actions) + ListView for content
- **Focal point:** Band name section (heading + avatar) positioned at top of scrollable content — primary visual anchor for identifying which band is displayed
- **Sections:** 
  1. Band info (name heading, avatar)
  2. Members section (label + member list)
  3. Invite code section (label + code display + copy button)
  4. Actions (Edit, Leave, Delete [owner only])
- **Spacing:** 24px padding around sections, 16px between section subsections, 8px between list items
- **Member list items:** ListTile or simple Row with username (bodyMedium) and remove icon (owner only, red)
- **Copy button:** Simple "Copy" text button or icon button next to invite code
- **Actions:** Rows of buttons at bottom or grouped in a section. Destructive actions (Leave, Delete) use red/error color

### Create Band Screen

- **Layout:** Scaffold with AppBar ("Create a new band" title) + form in body + create button
- **Form fields:** Single text input for band name (labelLarge label, 16px padding)
- **Button:** "Create" ElevatedButton (primary color), full width or standard width
- **Spacing:** 24px top padding, 16px between form fields and button
- **Cancel:** Back button in AppBar (standard Material behavior)

### Join Band Dialog

- **Layout:** Material AlertDialog with title, content, actions
- **Title:** "Join a band"
- **Content:** Text input field with label "Invite code" (hint: "Paste the code here")
- **Actions:** "Cancel" TextButton, "Join" ElevatedButton (primary)
- **Spacing:** Material defaults (16px padding, 8px between buttons)

### Confirm Dialogs

All follow Material AlertDialog pattern:

**Delete Band (type-to-confirm):**
- Title: "Delete [band name]?"
- Body: Explanation + "Type the band name to confirm. This action cannot be undone..."
- Form field: "Band name" input (initially empty)
- Actions: "Cancel" TextButton, "Delete" ElevatedButton (red/error color, initially disabled until input matches band name exactly)

**Leave Band:**
- Title: "Leave [band name]?"
- Body: "You will no longer be a member of this band."
- Actions: "Cancel" TextButton, "Leave" ElevatedButton (red/error color)

**Remove Member:**
- Title: "Remove [username] from [band name]?"
- Body: "[username] will no longer be a member of this band."
- Actions: "Cancel" TextButton, "Remove" ElevatedButton (red/error color)

## Interaction Patterns

### Navigation

- **Bands list → Band detail:** Tap band list item
- **Bands list → Create band screen:** Tap FAB, then "Create band" from menu (D-09)
- **Bands list → Join band dialog:** Tap FAB, then "Join with code" from menu (D-09)
- **Create/Join → Band detail:** After successful create/join, navigate to band detail screen (D-12, NOT back to list)
- **Band detail → Bands list:** After leaving or deleting band, pop back to list (D-15)
- **Band detail → Edit band:** Tap "Edit" action, open edit screen (edit is separate screen, mirrors create flow)

### Dialogs & Confirmations

- **Join code dialog (D-11):** Modal dialog, full keyboard, autofocus on text field
- **Delete band dialog (D-13):** Modal dialog, type-to-confirm pattern (delete button disabled until input matches exact band name)
- **Leave/Remove dialogs (D-14):** Standard material confirm dialogs (lighter than type-to-confirm)

### State Transitions

- **Optimistic updates:** After successful POST/PUT/DELETE, immediately update local cache before full refresh
- **Mutations:** All create/join/edit/leave/remove actions require network (no offline mutation queue per project constraints)
- **Snackbar/Toast notifications:** Brief confirmation ("Copied!", "Band created!", "Left band") after success — no toast errors (use inline error display instead)
