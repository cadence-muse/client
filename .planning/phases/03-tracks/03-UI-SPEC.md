# Phase 3 — UI Design Contract

> Visual and interaction contract for Tracks CRUD and global Tracks tab. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Flutter Material Design 3 |
| Icon library | Material Icons |
| Font | System default (platform-specific via Flutter) |

**Rationale:** This is a Flutter app (not web React); design system established in Phase 1-2 uses Flutter's built-in Material Design components. No third-party component library or design token tool needed.

---

## Spacing Scale

Established in Phase 1-2, consistent 4px increments (Flutter convention):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Internal widget padding (rarely user-facing) |
| sm | 8px | Tight spacing within sections (e.g., SizedBox between stacked elements) |
| md | 12px | Compact list item padding or margins |
| lg | 16px | Default element spacing, list item horizontal padding |
| xl | 24px | Section padding, AppBar spacing, major gaps |
| 2xl | 32px | Layout margins (uncommon in Phase 3) |
| 3xl | 48px | Page-level breaks (uncommon in Phase 3) |

**Exceptions:** Duration value displayed as `24px` width/height for legibility as mm:ss text (e.g., `3:45`); not a spacing increment.

---

## Typography

Follows Flutter Material 3 defaults (ThemeData.light/dark via ColorScheme.fromSeed):

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 (regular) | 1.43 | Track list item descriptions, member lists, dialog body text |
| Label | 14px | 500 (medium) | 1.43 | Section headings (textTheme.labelLarge), form labels |
| Heading | 28px | 600 (semibold) | 1.18 | Screen titles, band/track detail headers (textTheme.headlineMedium) |
| Display | 32px | 700 (bold) | 1.14 | Rarely used in Phase 3; reserved for future emphasis |

**Rationale:** Material 3 theme provides these via `TextTheme`; Phase 1-2 established the headlineMedium for major headings and labelLarge for section labels. Phase 3 extends with consistent body (14px) and label (14px) usage.

---

## Color

Flutter Material 3 with `ColorScheme.fromSeed(seedColor: Colors.green)`:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Green (#4CAF50 seed-derived) | AppBar background, primary surface |
| Secondary (30%) | Surface color (light: ~#F5F5F5, dark: ~#121212) | Card backgrounds, content areas |
| Accent (10%) | Green variant (secondary green from seed) | (Reserved for future use; not used in Phase 3) |
| Destructive | Error color (red, seed-derived ~#B00020) | Delete/remove actions only (icon + text button in red) |

**Accent reserved for:** Currently none in Phase 3; reserved for future phase emphasis patterns (Phase 4+ may use for setlist-specific highlights).

**Destructive action pattern:** All delete/remove actions use `colorScheme.error` for icon and button styling (matches Phase 2 band delete/leave/remove-member pattern). See Copywriting section for confirmation dialog styling.

## Copywriting Contract

Phase 3 screens and dialogs use consistent, action-oriented copy following Phase 2 patterns:

| Element | Copy |
|---------|------|
| **TrackListScreen (per-band) title** | `'Tracks'` (in AppBar) |
| **GlobalTracksScreen (cross-band) title** | `'Tracks'` (in AppBar, bottom nav) |
| **Primary CTA — add track** | `'Add track'` (FloatingActionButton label, tooltip) |
| **Primary CTA — form submit** | `'Save'` (FilledButton on AddTrackScreen and EditTrackScreen) |
| **Secondary CTA — form cancel** | `'Cancel'` (via AppBar back or TextButton) |
| **Empty state (no tracks in band)** | **Heading:** `'No tracks yet'` **Body:** `'Create a track or ask a bandmate to add one.'` **CTA:** `'Add track'` (ElevatedButton, mirrors Phase 2 no-bands pattern) |
| **Empty state (global Tracks tab, no tracks at all)** | **Heading:** `'No tracks'` **Body:** `'Create tracks in a band to see them here.'` **CTA:** `'View bands'` (optional, navigates to Bands tab) |
| **Error state (track load failure)** | **Heading:** `"Couldn't load tracks"` **Body:** `'Please check your connection and try again.'` **CTA:** `'Retry'` (ElevatedButton, mirrors Phase 2 error pattern) |
| **Delete confirmation — track delete** | **Title:** `'Delete {trackTitle}?'` **Body:** `'This action cannot be undone.'` **Buttons:** `'Cancel'` (TextButton, left) and `'Delete'` (FilledButton with error color, right) |
| **Form validation error — required field empty** | `'Enter {field name}'` (e.g., `'Enter a track title'`, `'Enter artist name'`) |
| **Form validation error — duration invalid** | `'Enter a valid duration'` (if user enters non-numeric or out-of-range seconds) |
| **Form success — track created** | SnackBar: `'{trackTitle} added!'` (mirrors Phase 2 band creation) |
| **Form success — track updated** | SnackBar: `'{trackTitle} updated!'` |
| **Form success — track deleted** | (After 2x pop navigation, no SnackBar shown; user returns to band track list) |
| **Global Tracks filter button label** | `'Filter by band'` or `'All bands'` (dropdown trigger, changes label based on selected filter) |

**Rationale:** All copy follows Phase 2 established patterns (no-{entities}-yet, couldn't-load, {action}-{item}, retry-error). Action-oriented CTAs use verbs + nouns. Destructive confirmations use lightweight (non-type-to-confirm) pattern per D-11.

## Component Specifications

### TrackListScreen (per-band)

**Structure:**
- `Scaffold` with `AppBar(title: 'Tracks')`
- `FloatingActionButton` with `Icons.add` (tap → navigate to AddTrackScreen)
- `ListView.separated` with track list rows, or empty state, or error state

**Track List Row (ListTile):**
- **Leading:** Optional avatar/icon (no track cover image in Phase 3; consider plain icon like `Icons.music_note`)
- **Title:** Track title (max 1 line, ellipsis)
- **Subtitle:** Artist name (max 1 line, ellipsis)
- **Trailing:** Duration as `mm:ss` (right-aligned, monospace font, ~24px width for text like `3:45`)
- **OnTap:** Navigate to TrackDetailScreen(bandId, trackId)
- **Divider:** `Divider(height: 1)` between rows (via `ListView.separated`)

**Spacing:**
- List item padding: 16px horizontal (Flutter ListTile default)
- No explicit header/footer padding beyond SafeArea
- Empty state / error state: centered column with 24px padding (matches Phase 2 bands pattern)

---

### TrackDetailScreen

**Structure:**
- `Scaffold` with `AppBar(title: track title, actions: [edit icon])`
- `ListView` showing track details:
  - Title (headlineMedium, 28px)
  - Artist (body, 14px)
  - Duration (body, 14px, monospace for `mm:ss`)
  - Tempo (body, 14px, if present)
  - Key (body, 14px, if present — e.g., "C major")
  - Notes (body, 14px, multiline, if present)
- If owner-editable: Edit button in AppBar (IconButton, `Icons.edit`)
- If owner-editable: Delete ListTile at bottom (owner-gated, error-color text + icon, same pattern as Phase 2 band detail)

**Spacing:**
- 24px top padding after AppBar
- 12px between most fields
- 24px before Delete section
- 16px padding for Divider and ListTile sections

---

### AddTrackScreen (full-screen form)

**Structure:**
- `Scaffold` with `AppBar(title: 'Add track')`
- `SafeArea` + `SingleChildScrollView`
- `Form` containing:
  1. **Title field** (TextFormField, required)
  2. **Artist field** (TextFormField, required)
  3. **Duration field** (TextFormField, optional, input format: seconds as integer)
  4. **Tempo field** (TextFormField, optional, input format: BPM as integer)
  5. **Key field** (DropdownButtonFormField, optional, 24 values: C, Cm, C#, C#m, ... B, Bm)
  6. **Notes field** (TextFormField, optional, multiline)
  7. **Error message** (if any API call fails)
  8. **Submit button** (FilledButton, label: `'Save'`)

**Form Fields:**
- **TextFormField spec:**
  - `decoration: InputDecoration(labelText: '{field name}', border: OutlineInputBorder())`
  - `validator:` checks required fields (title, artist) and format (duration as int, tempo as int)
  - `textInputAction: TextInputAction.done` for final field
  - `onFieldSubmitted:` trigger submit for final field
- **DropdownButtonFormField (Key):**
  - Items: 12 root notes × 2 (major/minor) = 24 total
  - Display format: `'C'`, `'Cm'`, `'C#'`, `'C#m'`, ... `'B'`, `'Bm'`
  - Value stored as string in API (no enum validation)
  - Default: null (empty selection)

**Spacing & Layout:**
- Body padding: `EdgeInsets.all(24)`
- Form field spacing: `SizedBox(height: 24)` between fields
- Error message: `SizedBox(height: 16)` before submit button
- Button: full-width, `FilledButton`
- Loading state: spinner replaces button text (matches Phase 2)

---

### EditTrackScreen (full-screen form)

**Identical to AddTrackScreen in layout, except:**
- `AppBar(title: 'Edit track')`
- All 6 fields pre-populated with current values
- Submit button label: `'Save'` (same)
- On success: pop back to TrackDetailScreen (not BandDetailScreen)

---

### TrackDetailScreen — Delete Action

**Delete ListTile (owner-gated, matches Phase 2 band detail):**
- Visible only if user is band owner (D-05 owner gating from Phase 2 context)
- `Divider` above
- `ListTile` with:
  - Leading: `Icon(Icons.delete, color: colorScheme.error)`
  - Title: `Text('Delete', style: TextStyle(color: colorScheme.error))`
  - OnTap: `showDialog()` → ConfirmDeleteTrackDialog

**ConfirmDeleteTrackDialog (lightweight, non-type-to-confirm):**
- `AlertDialog` with:
  - `title: Text('Delete {trackTitle}?')`
  - `content: Column(mainAxisSize: MainAxisSize.min, ...) { Text('This action cannot be undone.'), if error: error text }`
  - `actions: [TextButton(Cancel), FilledButton(Delete, error color)]`
- On confirm: API DELETE, then 2x pop (dialog → detail → list)
- Loading: spinner replaces button text

---

### GlobalTracksScreen (cross-band Tracks tab)

**Structure:**
- `Scaffold` with `AppBar(title: 'Tracks')`
- Filter controls (below AppBar or in body header):
  - **Filter dropdown:** Label shows current filter (e.g., `'All bands'` or `'{Selected Band Name}'`)
  - **Dropdown options:** All bands (empty/null filter) + each user's band (bandId, bandName)
  - Selecting a band filters list via `bandId` query param to new `GET /api/track/list` endpoint
- `ListView.separated` showing filtered track list (same row style as per-band TrackListScreen):
  - Title + Artist + Duration (right side, monospace mm:ss)
  - **Additional:** Band name as left-side badge/chip (visual distinction from per-band list)
- Empty state / error state (same as per-band list)

**Band Badge Styling:**
- Small chip or text badge showing band name
- Position: left side, before title (or inline with title)
- Style: secondary background (surface color) with text, ~8px padding, rounded corners
- Prevents user from forgetting which band owns each track in flat global list

**Spacing:**
- Filter dropdown: 16px padding from top (below AppBar)
- List rows: same as per-band (16px horizontal padding)
- Badge: inline with title, left side, ~8px horizontal gap between badge and title text

## UI Considerations

### State Coverage Resolved

| Category | Element(s) | Status | Resolution |
|----------|------------|--------|-----------|
| **empty** | TrackListScreen list (no tracks in band) | ✅ covered | Empty state renders `'No tracks yet'` heading + `'Create a track or...'` body + `'Add track'` CTA (center-aligned, matches Phase 2 no-bands pattern) |
| **empty** | GlobalTracksScreen list (no tracks across all bands) | ✅ covered | Empty state renders `'No tracks'` heading + `'Create tracks in a band...'` body (no CTA button; "View bands" optional) |
| **loading** | TrackListScreen / GlobalTracksScreen list fetch | ✅ covered | CircularProgressIndicator centered (matches Phase 1-2 pattern) |
| **loading** | Add/Edit form submission | ✅ covered | Spinner replaces FilledButton text; button disabled during POST/PUT (matches Phase 2 form pattern) |
| **error** | Track list fetch failure | ✅ covered | Center-aligned error state with `"Couldn't load tracks"` heading + `'Please check your connection...'` body + `'Retry'` CTA (matches Phase 2 error pattern) |
| **error** | Form submission failure (API error) | ✅ covered | Error message displayed in form below TextField, in error color; form fields remain interactive for retry |
| **error** | Delete action failure | ✅ covered | Error message displayed in ConfirmDeleteTrackDialog content, in error color; dialog buttons remain interactive |
| **long-text** | Track title in list row | ✅ covered | `maxLines: 1, overflow: TextOverflow.ellipsis` |
| **long-text** | Artist name in list row | ✅ covered | `maxLines: 1, overflow: TextOverflow.ellipsis` |
| **long-text** | Track title in detail screen | ✅ covered | `maxLines: 1, overflow: TextOverflow.ellipsis` (same as Phase 2 band title pattern) |
| **long-text** | Notes field (optional, multiline) | ✅ covered | TextFormField with `maxLines: null` (grows to fit content, or scrolls in form) |
| **overflow** | Track list with many items | ✅ covered | ListView handles scrolling; no pagination or lazy-loading in Phase 3 scope (cache-first loading from `lib/cache/cache_service.dart` per Phase 1-2 pattern) |
| **zero-one-many** | Band dropdown in GlobalTracksScreen filter | 🧪 backstop | "All bands" label shown when no filter active; dropdown shows 1 entry (just "All bands") if user has 0 bands (should be rare/impossible at this point, but not explicitly designed for). Planner assumes user always has ≥1 band when viewing global Tracks tab (navigation gating via bottom nav may prevent access until a band exists). |
| **partial** | GlobalTracksScreen with some bands having no tracks | ✅ covered | Flat list shows only tracks from bands with content; filter dropdown lists all user's bands; selecting a band with no tracks shows empty state `'No tracks in {band name}'` or generic `'No tracks'` (re-uses same empty copy as overall empty state). |
