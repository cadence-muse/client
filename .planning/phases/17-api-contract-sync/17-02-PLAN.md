<objective>
Fix `AddSetlistTracksDialog`'s D-03 discard bug: the dialog's debounced `listBandTracks(searchQuery: ...)` response is currently thrown away (`.catchError((_) => <Map<String,dynamic>>[])`, result unused) while online, so the checklist never re-filters on a real server search even though the network request fires. Render that response instead — the offline substring fallback (D-05, unaffected by this plan) stays exactly as-is.

Purpose: Users searching the setlist track picker while online currently get zero benefit from the network request their typing triggers — this plan makes that request's response actually reach the screen (API-01).
Output: `AddSetlistTracksDialog` renders live server search results while online.
</objective>
