<objective>
Migrate `listUserTracks`/`listUserSetlists` from POST+body to GET+query parameters (mirroring the already-correct `listBandTracks`), and wire real, debounced, online-gated search boxes onto the global cross-band Tracks tab (`TracksScreen`) and Setlists tab (`SetlistsScreen`) — the two bottom-nav destinations the ROADMAP's "cross-band Tracks and Setlists tab searches" success criterion actually refers to (D-01, API-01).

**File-name correction:** CONTEXT.md/RESEARCH.md/17-PATTERNS.md cite `lib/features/tracks/track_list_screen.dart` and `lib/features/setlists/setlist_list_screen.dart` as D-01's targets. Those are the wrong files — `TrackListScreen`/`SetlistListScreen` are the *per-band* list screens (`required this.bandId`, backed by `listBandTracks`/`listBandSetlists`), unrelated to the global tab. The actual global, cross-band "Tracks tab"/"Setlists tab" screens — the ones with the band-filter dropdown, backed by `userTracksListDataProvider`/`userSetlistsListDataProvider` (which already call `listUserTracks`/`listUserSetlists`, per `tracks_provider.dart:311`/`setlists_provider.dart:432`) — are `lib/features/tracks/tracks_screen.dart` (`TracksScreen`, doc comment: "The global, cross-band Tracks tab") and `lib/features/setlists/setlists_screen.dart` (`SetlistsScreen`, doc comment: "The global, cross-band Setlists tab"). D-01's own text allows for this ("`track_list_screen.dart`, `setlist_list_screen.dart` **or their screen wrappers**") — this plan implements D-01 against the correct screens.

Purpose: Real server-side search on the app's two busiest cross-band list views, replacing the dead `searchQuery` wiring that already exists in the provider signatures but is never called with a value.
Output: `TracksScreen`/`SetlistsScreen` with working debounced search; `listUserTracks`/`listUserSetlists` on the wire contract.
</objective>
