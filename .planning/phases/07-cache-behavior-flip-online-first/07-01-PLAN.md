banner reword) against a real, already-tested subsystem before replicating it
9 more times, so any structural mistake is caught after one commit, not ten.

`BandsScreen`/`BandDetailScreen` rewired accordingly; `OfflineBanner` reworded

the new behavior.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Device connectivity signal -> fetch/cache policy | `isOnlineProvider` (connectivity_plus radio state, crossing an OS platform channel) now directly gates whether `BandsListData`/`BandDetailData` trust the network or fall back to local cache |
| Cached Hive data -> UI render | Previously-fetched, already-trusted JSON is rendered as-is on the offline/fetch-fail path; no new deserialization surface introduced |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Tampering | `BandsListData`/`BandDetailData` `_version` guard | medium | mitigate | The online-first `build()` rewrite preserves the existing `_version` monotonic-counter guard verbatim (untouched by this task) — a slow in-flight fetch still cannot silently overwrite a newer local mutation (`renameBand`/`updateName`), same protection as before this phase (WR-02, unchanged) |
| T-07-02 | Spoofing | `isOnlineProvider` (connectivity_plus radio state, not reachability) | low | accept | connectivity_plus reports device radio state, not actual internet reachability. D-03's silent-fallback-to-cache on any fetch failure already absorbs the "online but no real internet" case without a distinct security control; no auth/session state is affected by a wrong online/offline read |
| T-07-03 | Information Disclosure | `OfflineNoCacheException`/`OfflineNoCacheView` | low | accept | The exception carries a fixed diagnostic string only (no user data, no stack trace shown to the user); the view renders static copy, not any cached payload |
</threat_model>
