<objective>
Replace the raw-text date `TextFormField` in both setlist forms with a `readOnly` field that opens the platform's native `showDatePicker` on tap, per SETL-13 and locked decisions D-01–D-04 from `15-CONTEXT.md`. `CreateSetlistScreen` (Task 1) establishes the picker pattern end-to-end as the phase's tracer slice; `EditSetlistScreen` (Task 2) expands it, adding the existing-date pre-population and malformed-date fallback that only the edit form needs.

Output: Both setlist screens use `showDatePicker` instead of keyboard entry; new widget tests cover the picker-open, date-round-trip, range-bound, clear-icon, and malformed-date-fallback behaviors.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| User tap -> local DateTime -> API request body | `showDatePicker`'s selection is client-formatted (`toIso8601String().split('T')[0]`) and sent as `eventDate` in `createSetlist`/`updateSetlist` requests — the server independently validates the `date` format per `publicapi.yml` |
| Persisted `eventDate` -> `DateTime.parse` -> `initialDate` | `EditSetlistScreen` parses a server-returned string back into a `DateTime` to seed the picker; this is the only place untrusted-shaped data flows back into date logic |
