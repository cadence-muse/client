## Copywriting Contract

### Duration Input & Display

| Element | Copy | Notes |
|---------|------|-------|
| Field Label (forms) | "Duration" | Single word, replaces current "Duration (seconds)" label; unit (mm:ss) implied by placeholder and auto-format UX |
| Field Placeholder | "0:00" | Shows the expected mm:ss format to users (static placeholder, not cleared on focus) |
| Helper Text (optional) | "e.g. 2:30 for 2 minutes 30 seconds" | Optional inline helper below label to clarify format on first view; can be omitted if space-constrained |
| Error: Incomplete Input | "Enter duration in mm:ss format (e.g. 0:30)" | Shown on submit if field contains partial/invalid characters like "2:" or "5:60" |
| Error: Seconds >= 60 | "Seconds must be 0–59 (e.g. 2:30, not 2:75)" | Shown on submit if seconds component is invalid; pairs with specific malformed-input rejection |
| Error: Negative Values | "Duration cannot be negative" | Unlikely with numeric keyboard, but explicit if paste/programmatic input allows it |
| Validation Feedback Timing | Inline on submit only | Matches existing WR-02 pattern (create_track_screen.dart); not shown per-keystroke as user types |
| Empty Field | (no error) | Blank field is valid and optional; submits as `null` `durationSeconds` — no change from current behavior |
| Max Value (99:59) | (implicit, auto-capped) | Entering "100:00" or more is prevented by TextInputFormatter; last digit(s) that would exceed 99:59 are not inserted |

### Track List / Detail Display

| Element | Copy / Format | Notes |
|---------|------|-------|

## Component Specifications

### 1. Duration Input Field (D-02, D-03, D-04, D-06)

**Purpose:** Accept duration in mm:ss format with auto-formatting and validation.

**Structure:**
```
┌──────────────────────────┐
│ Duration                 │  ← labelText
│ 0:00                     │  ← placeholder text
│ [2|3|0]                  │  ← user typing "230"; shown as "2:30" by formatter
│ Enter duration...        │  ← helperText (optional, can be omitted)
│                          │
│ Seconds must be 0–59     │  ← errorText (only on validation failure)
└──────────────────────────┘
```

**Implementation Details:**

**Widget:** `TextFormField` (existing pattern from `create_track_screen.dart`)

**Key Properties:**
- `controller`: `TextEditingController` for `durationController` (existing)
- `keyboardType`: `TextInputType.number` (numeric keyboard for mobile)
- `inputFormatters`: [Custom `DurationTextInputFormatter`] — implements D-02/D-03/D-04
  - Right-to-left digit shift: `"2"` → `"0:02"`, `"230"` → `"2:30"`, `"2305"` → `"23:05"`
  - Maximum value: `99:59` (cap via D-03; any input that would exceed this is rejected)
  - Backspace behavior: deletes last digit and reformats (e.g., `"2:30"` + backspace → `"0:23"` per D-04)
  - Allowed characters: digits 0–9 only
- `decoration`: `InputDecoration`
  - `labelText`: `"Duration"`
  - `hintText`: `"0:00"` (shows expected format)
  - `helperText`: `"e.g. 2:30 for 2 minutes 30 seconds"` (optional; can omit if space is constrained)
  - `border`: `OutlineInputBorder()` (consistent with other form fields in create_track_screen.dart)
  - `errorText`: populated by `validator` on submit
- `validator`: Checks for incomplete/invalid mm:ss format on submit attempt
  - Empty field: returns `null` (valid, per D-06)
  - Field with partial input like `"2:"` or `":"`: returns error message `"Enter duration in mm:ss format (e.g. 0:30)"`
  - Field with seconds ≥ 60 (if formatter fails to reject): returns `"Seconds must be 0–59 (e.g. 2:30, not 2:75)"`
  - Field with valid mm:ss: returns `null` (valid)
- `onChanged`: (optional) can be omitted; formatter handles UI updates automatically
- `readOnly`: `false` (input is interactive)

**Validation Timing (D-05):**
- Inline error text is shown only on form submit attempt (not per-keystroke)
- Matches existing WR-02 pattern in `create_track_screen.dart` where non-empty malformed input is flagged on submit
- The `DurationTextInputFormatter` prevents most malformed states by construction (auto-formats as user types), so the validator only needs to catch edge cases like incomplete input left at submit time

**Value Submission:**
- On form submit, convert field text to seconds:
  ```dart
  int? _parseDurationSeconds(String text) {
    // Expected format: "mm:ss", e.g. "2:30" → 150 seconds
    final parts = text.split(':');
    if (parts.length != 2) return null;
    final minutes = int.tryParse(parts[0]);
    final seconds = int.tryParse(parts[1]);
    if (minutes == null || seconds == null || seconds > 59) return null;
    return minutes * 60 + seconds;
  }
  ```
- Submit via `durationSeconds: _parseDurationSeconds(_durationController.text.trim())`
- If parsing fails (should not happen with valid formatter), return `null` to match D-06 optional-field behavior

**Notes:**
- Custom formatter is implemented as a new class `DurationTextInputFormatter extends TextInputFormatter` in `lib/features/tracks/track_formatting.dart` (same file as existing `DurationFormatting` extension, for co-location)
- Formatter is reused identically on both `create_track_screen.dart` and `edit_track_screen.dart`
- No external package dependency; formatter uses only Flutter's built-in `TextInputFormatter` API

### 2. Duration Display Format (D-01)

**Purpose:** Render track and setlist duration consistently as mm:ss across all screens.

**Format:** `mm:ss` with unbounded minutes (e.g., "2:30", "42:15", "120:00")

**Implementation Details:**

**Existing Extension (reused as-is):**
- `DurationFormatting.asMinutesSeconds` in `lib/features/tracks/track_formatting.dart` is the canonical display format
- Logic: `'${this ~/ 60}:${(this % 60).toString().padLeft(2, '0')}'`
- Example: `225` seconds → `"3:45"`; `2555` seconds → `"42:35"`

**Usage Locations (all updated to use `asMinutesSeconds`):**

| Screen | Element | Current Format | New Format |
|--------|---------|-----------------|-----------|
| Track List (`track_list_screen.dart`) | Duration trailing text | "3:45" (already mm:ss) | "3:45" (no change) |
| Track Detail (`track_detail_screen.dart`) | Duration label value | "3:45" (already mm:ss) | "3:45" (no change) |
| Tracks Tab (`tracks_screen.dart`) | Duration in list rows | "3:45" (already mm:ss) | "3:45" (no change) |
| Setlist List (`setlist_list_screen.dart`) | Duration component | "42m 35s" (words format) | "42:35" (unified mm:ss) |
| Setlist Detail (`setlist_detail_screen.dart`) | Duration label | "42m 35s" (words format) | "42:35" (unified mm:ss) |
| Setlists Tab (`setlists_screen.dart`) | Duration in list rows | "42m 35s" (words format) | "42:35" (unified mm:ss) |
| Setlist Track Add Dialog (`add_setlist_tracks_dialog.dart`) | Track duration columns | "3:45" (mm:ss) | "3:45" (no change) |
| Setlist Total Composition | `tracksAndDuration()` helper result | "8 tracks, 42m 35s" (mixed) | "8 tracks, 42:35" (unified) |

**Breaking Changes (Reversibility: costly per D-01):**
- `asMinutesAndSeconds` extension in `lib/features/setlists/setlist_formatting.dart` is **retired** (no longer used)
- All callers of `asMinutesAndSeconds` and the helper `tracksAndDuration()` that used it are updated to call the unified `asMinutesSeconds` instead
- Search for `asMinutesAndSeconds` in codebase; should have zero remaining references after Phase 11

**Notes:**
- Minutes are left-aligned (no zero-padding on the minutes component): `"2:30"`, not `"02:30"`
- Seconds are always zero-padded to 2 digits: `"2:05"` not `"2:5"`
- No special casing for totals > 60 minutes — plain mm:ss handles all values: `"120:15"` is valid

### 3. Duration Parsing Helper (D-06)

**Purpose:** Convert mm:ss input field text to `durationSeconds` integer for API submission.

**Function Signature:**
```dart
int? parseDurationSeconds(String text) {
  final trimmed = text.trim();
  if (trimmed.isEmpty) return null; // Optional field per D-06
  
  final parts = trimmed.split(':');
  if (parts.length != 2) return null; // Expected "mm:ss"
  
  final minutes = int.tryParse(parts[0]);
  final seconds = int.tryParse(parts[1]);
  
  if (minutes == null || seconds == null) return null;
  if (seconds > 59) return null; // Seconds must be 0–59
  
  return minutes * 60 + seconds;
}
```

**Integration Points:**
- Called in `_submit()` of `create_track_screen.dart` and `edit_track_screen.dart`
- Replaces current `int.tryParse(_durationController.text.trim())`
- Usage: `durationSeconds: parseDurationSeconds(_durationController.text)`
- Location: Place in `lib/features/tracks/track_formatting.dart` alongside `DurationFormatting` extension for co-location

**Notes:**
- Returns `null` for empty field (preserves optional behavior per D-06)
- Returns `null` for any unparseable/invalid input (safety fallback if formatter somehow allows invalid input)
- Assumes `DurationTextInputFormatter` has already validated format; this function is a secondary safety check

## Interaction Flow (Happy Path)

### Path 1: Create Track with Duration

```
Create Track Screen
  ↓ User taps Duration field
  ↓ Types digits: "2" → auto-formats to "0:02"
  ↓ Types more: "230" → auto-formats to "2:30"
  ↓ [form shows populated duration field in mm:ss]
  ↓ [user taps Submit]
  ↓ Validator: parse "2:30" → checks for errors → none found
  ↓ Convert "2:30" to 150 seconds (2*60 + 30)
  ↓ POST to API with durationSeconds: 150
  ↓ API responds with created track
  ↓ Navigator.pop() → user returns to band detail or track list
  ↓ Track list shows "2:30" in mm:ss format
  → Success
```

### Path 2: Invalid Duration (Seconds ≥ 60)

```
Create Track Screen
  ↓ User taps Duration field
  ↓ Types "2:75" (manually pastes or rapid-types past formatter)
  ↓ [TextField shows "2:75" if formatter doesn't catch it]
  ↓ [user taps Submit]
  ↓ Validator: parse "2:75" → seconds = 75 > 59 → ERROR
  ↓ Error text shown below field: "Seconds must be 0–59 (e.g. 2:30, not 2:75)"
  ↓ Form submission blocked
  ↓ [user corrects to "2:30"]
  ↓ [user taps Submit again]
  ↓ Validator: "2:30" → valid → proceed
  → Success
```

### Path 3: Empty Duration (Optional)

```
Create Track Screen
  ↓ User leaves Duration field blank
  ↓ [user taps Submit]
  ↓ Validator: empty field → returns null (valid)
  ↓ Submit proceeds with durationSeconds: null
  ↓ API creates track without duration
  → Success (track has no duration)
```

### Path 4: Edit Track Duration

```
Edit Track Screen (pre-populated with existing track data)
  ↓ Duration field shows existing value formatted: "3:45"
  ↓ User taps field and edits
  ↓ User backspaces to clear and types "4:20"
  ↓ [field auto-formats during typing]
  ↓ [user taps Submit]
  ↓ Validator: "4:20" → valid
  ↓ Convert to 260 seconds
  ↓ PUT to API with all track fields including durationSeconds: 260
  ↓ API responds with updated track
  ↓ Track list re-renders with new duration "4:20"
  → Success
```

### Path 5: Display Unification (Setlist Total)

```
Setlist Detail Screen
  ↓ [screen loads setlist with 8 tracks totaling 2555 seconds]
  ↓ Display: "8 tracks, 42:35" (unified mm:ss format)
  ↓ [previously was "8 tracks, 42m 35s"; now consistent with track durations]
  → Consistency achieved across all screens
```

## Executor Decisions (Claude's Discretion)

| Decision | Options | Recommendation | Reasoning |
|----------|---------|-----------------|-----------|
| Helper text visibility | Include "e.g. 2:30..." helper text or omit | Include on first form load; consider omitting on edit screens if space constrained | Helps new users understand mm:ss format; edit screens can rely on the formatter's feedback |
