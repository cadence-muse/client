<objective>
Add three Homepage quick actions — Add Band, Add Song, Add Setlist — so a user can jump straight from Home into the relevant create screen without extra navigation (ROADMAP Phase 9 goal; HOME-01, HOME-02).

Home's `_buildContent()` is restructured into one unified layout for both zero-bands and populated states (D-03): a rounded welcome card (D-01), a "Quick Actions" header (D-02), and a 3-button row (D-02/D-10) where Add Band always navigates directly to `CreateBandScreen` (D-11) and Add Song/Add Setlist are disabled until `bandsCount > 0` (D-09), at which point they open a shared band-picker bottom sheet (D-05/D-06/D-07/D-08) that hands off the selected `bandId` to `CreateTrackScreen`/`CreateSetlistScreen` (D-11).

Two decisions are deliberately non-tasks and are called out here for traceability rather than in a task action: D-04 (`bands_screen.dart`'s FAB + Create/Join bottom sheet is untouched — do not modify that file) and D-12 (no new refresh wiring is added on Home — the existing tab-switch invalidation of `homepageDataProvider`, already in `home_screen.dart`, is sufficient).

Purpose: Reduce navigation depth for the app's most common creation flows (add a band, add a song, add a setlist) directly from the screen users land on first.
Output: Restructured `lib/features/home/home_screen.dart`, new `lib/features/home/band_picker_sheet.dart`, and passing widget-test coverage for both.
</objective>
