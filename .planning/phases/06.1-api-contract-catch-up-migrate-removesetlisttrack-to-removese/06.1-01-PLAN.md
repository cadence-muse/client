<objective>
Migrate three `public_api.dart` methods — `removeSetlistTrack`, `listUserTracks`, `listUserSetlists` — to match the `lib/api/publicapi.yml` wire contract as it stands after commit `fe72e78` ("Update schema"). That commit changed the schema but the client was never updated to match, so these three operations currently fail against the live API: the old single-track `DELETE .../setlist/{setlistId}/track/{trackId}` route no longer exists (replaced by a batch `DELETE .../tracks` with a `trackIds` body), and both `GET /api/track/list` and `GET /api/setlist/list` no longer exist (replaced by `POST` equivalents that also accept an optional `searchQuery` body field).

This is an **inserted urgent catch-up phase** (Phase 06.1, per STATE.md's "Roadmap Evolution" entry) with no `REQUIREMENTS.md` requirement IDs of its own — `requirements: []` in this plan's frontmatter is intentional, not an oversight. ROADMAP.md's placeholder goal for this phase ("[Urgent work - to be planned]") gets filled in as part of this plan's execution (see the `update_roadmap` step the orchestrator runs after this plan is written).

**Explicitly out of scope** (do not touch):
- `ListBandTracks` (`GET /api/band/{bandId}/track/list`) — unchanged, still GET. Phase 10's concern (`SETL-12`, a *different* endpoint's `searchQuery` field — do not confuse with this phase's `ListUserTracks`/`ListUserSetlists` `searchQuery`).
- `ListBandSetlists` (`GET /api/band/{bandId}/setlist/list`) — unchanged, still GET.
- `AddSetlistTracks` (`POST .../setlist/{setlistId}/tracks`) — same URL/body shape before and after; only its documented success response code changed 204→200 in the spec. `ApiClient.send` only branches on `statusCode >= 400`, so this needs no code change — Task 3 confirms this with a full test-suite run rather than a code edit.
- `ChangeUserPassword`, `RotateBandInviteCode`, `TransferBandOwnership` — also touched by the `fe72e78` schema diff, but not part of this phase's stated scope (STATE.md names exactly the 3 migrations below). Not built here; flagged as a future-phase concern, not silently added.
- No search UI. `listUserTracks`/`listUserSetlists` gain an optional `searchQuery` parameter (the wire schema now supports it) purely for forward-compatible signature completeness — no caller passes it yet, and no search input widget is built in this phase.

Purpose: Unblock the v1.1 milestone's cross-band track/setlist lists and setlist track removal, which are currently broken against the live (post-`fe72e78`) API.
Output: `lib/api/public_api.dart` with all three methods matching the current schema; a new focused unit-test file proving the exact wire contract for all three; the one existing test that asserted the old DELETE shape corrected; full analyze/test suite green.
</objective>
