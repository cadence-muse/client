<objective>
Add track management to the setlist detail screen: adding one or more of the band's existing tracks in a single bulk call, removing a single track via a per-row icon, and the toggleable Edit mode (D-15) that gates both actions' visibility. This plan intentionally does NOT add drag-and-drop reordering (SETL-08, Plan 04) — it builds the Edit-mode scaffolding (the `_editMode` bool, the remove-icon row shape) that Plan 04 extends with drag handles, so the mode toggle itself needs no rework when reordering lands.

**Note on duration accuracy after mutation:** unlike Plan 02's edit form (which already knows every field's new value from the form itself and can `updateFields()` a local patch), adding or removing a track changes `durationSeconds` and `tracks.length` in a way the client cannot correctly compute without summing individual track durations — which SETL-09 and this plan's `must_haves.prohibitions` explicitly forbid. This plan therefore always re-fetches via each provider's existing `refresh()` method after a successful add/remove, rather than attempting a local-patch merge (contrast this with Plan 04's reorder, which changes track *order* only — not count or duration — and so *can* safely local-patch).

Purpose: close SETL-06/SETL-07, completing the "manage which tracks are on this setlist" half of track management before drag-and-drop reordering (Plan 04) closes the "in what order" half.
Output: `AddSetlistTracksDialog`, the `addSetlistTracks`/`removeSetlistTrack` API methods, and `SetlistDetailScreen`'s new Edit-mode toggle + remove-icon rows.
</objective>
