<objective>
Complete per-band setlist info CRUD by adding edit and delete on top of Plan 01's list/create/detail slice. A band member can now change a setlist's name/location/date and remove a setlist entirely, both reachable only from the setlist detail screen (per D-16/D-17/D-18/D-19).

**Note on ownership gating:** neither `BandSetlist` nor `SetlistListItem` in `lib/api/publicapi.yml` carries an `ownerId` field, and REQUIREMENTS.md's SETL-04/SETL-05 carry no owner qualifier (unlike BAND-05's explicit "Band owner can delete a band"). This mirrors Phase 3's TRACK-04/TRACK-05 precedent (03-02-PLAN.md's objective note) exactly: edit and delete are built ungated in this plan, with the server as the sole enforcer of band-membership access.

Purpose: close SETL-04/SETL-05 so per-band setlist *info* management is CRUD-complete before track add/remove/reorder (Plans 03/04) and the global cross-band tab (Plan 05) are layered on top.
Output: `EditSetlistScreen`, `ConfirmDeleteSetlistDialog`, and the `updateSetlist`/`deleteSetlist` API methods, wired from `SetlistDetailScreen`.
</objective>
