<objective>
Add drag-and-drop track reordering to the setlist detail screen's Edit mode (SETL-08), completing Phase 4's track-management trio started in Plan 03 (add/remove) and Plan 02 (info edit/delete).

**Deviation from 04-RESEARCH.md's package recommendation (read before starting):** 04-RESEARCH.md's "Package Legitimacy Audit" and 04-UI-SPEC.md's "Registry Safety" section both recommend adding `reorderable_grid_view` or `flutter_reorderable_list` from pub.dev, and 04-UI-SPEC.md's Design System section calls for a pre-Wave-1 "spike" to choose between them. This plan does neither. Flutter's SDK already ships `ReorderableListView` (and the lower-level `ReorderableDragStartListener`/`SliverReorderableList`) in `package:flutter/material.dart`, purpose-built for exactly this shape: a single vertical list of rows, drag-to-reorder, with an `onReorder(oldIndex, newIndex)` callback and a `buildDefaultDragHandles: false` escape hatch for placing a custom drag-handle icon per row (confirmed present in this project's installed Flutter 3.44.9 SDK at `packages/flutter/lib/src/material/reorderable_list.dart`; `ReorderableDragStartListener` confirmed at `packages/flutter/lib/src/widgets/reorderable_list.dart`). Track reordering here is a plain vertical list, not a grid-to-grid drag — the specific case the SDK widget was built for. Adding a third-party package for functionality the SDK already provides would be unnecessary dependency risk with no functional benefit; no package-legitimacy checkpoint applies since no new package is installed. If a future requirement needs true grid-to-grid dragging, that would be the point to revisit `reorderable_grid_view`.

**Note on layout — do not use ReorderableListView's header/footer params:** `ReorderableListView` does support `header:`/`footer:` widgets, but this plan does NOT use them. `SetlistDetailScreen`'s header info (name/location/date/duration), the Edit/Done toggle, and the delete `ListTile` (Plan 02) all stay outside the reorderable region, in a `Column` that only swaps its `Expanded` child between a plain `ListView` (read-only) and a `ReorderableListView` (edit mode) — this avoids mixed-scroll-physics complications and keeps the header/footer controls simple `Column` children unaffected by which list widget is currently showing.

Purpose: close the final piece of Phase 4's per-band track-management trio (SETL-06/07/08) before the global cross-band Setlists tab (Plan 05).
Output: `SetlistDetailScreen`'s edit-mode track list rendered via `ReorderableListView`, the `reorderSetlistTracks` API method, and `SetlistDetailData.reorderTracks`.
</objective>
