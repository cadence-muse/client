<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Device OS connectivity API -> app | `connectivity_plus` reads OS-reported radio/interface state; an external (device-local, not network) signal the app trusts as-is (D-01) |
| Cached data age -> UI display | The staleness badge is the only thing standing between a user and mistaking hours-old cached data for fresh data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Spoofing | `SyncStatusBadge` / staleness display | medium | mitigate | Every cache write stores a real `syncedAt`; a failed background refresh never advances it (D-06, enforced structurally — `_fetchAndCache` only writes to cache on success), so the badge can't show fresher-than-actual data |
| T-05-02 | Tampering + Information Disclosure | `cache_service.dart` timestamp envelope | low | mitigate | `syncedAt` is written atomically alongside `data` in the same Hive `put()` call (D-04) — no parallel store, no drift window where data and timestamp disagree |
| T-05-03 | Spoofing | `connectivity_provider.dart` / OS connectivity signal | low | accept | A compromised OS reporting false connectivity is out of this app's threat model; D-01 already accepts the lesser captive-portal false-positive as a known v1 gap |
| T-05-04 | Denial of Service (self) | `connectivity_plus` package dependency | low | accept | `05-RESEARCH.md`'s Package Legitimacy Audit already cleared `connectivity_plus` (OK/Approved, 5+ years, 5M+/week downloads, official GitHub source) — no `[ASSUMED]`/`[SUS]` disposition, no blocking checkpoint required |
