<objective>
Apply the same staleness-badge and connectivity-gated-mutation patterns established in 05-01/05-02/05-03 to the Setlists entity — the most structurally complex of the three, because setlist detail's Edit mode exposes two additional mutation surfaces (drag-to-reorder and per-track remove) that have no equivalent in Bands or Tracks.

Purpose: Extend D-12's "entry blocked at source" principle to a UI-mode toggle (not just a button that opens a new screen) — entering setlist detail's Edit mode is itself the entry point to reorder/remove mutations, so it must be gated exactly like a Create/Edit FAB.
Output: `setlists_provider.dart` gains per-key `syncedAt` exposure across its 3 cache keys; all 3 Setlists screens show the staleness badge; every Setlists mutation entry point (create, edit, delete, add-tracks, remove-track, reorder) is connectivity-gated.
</objective>
