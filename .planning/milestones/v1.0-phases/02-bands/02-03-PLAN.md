## Flagged Assumptions

- **BAND-06 edge probe returned `unclassified`** (not auto-resolvable — surfaced per the spec-less probe fallback's rule that unclassified rows stay unresolved). Root cause: `POST /api/band/join`'s response has no schema in `publicapi.yml` (`'200': description: Success` only) — the API contract genuinely does not return the newly-joined band's id, yet D-12 requires navigating straight to that band's detail screen. This plan's Task 2 resolves the common case via a client-side list-diff (no invented API field) and documents an explicit, graceful fallback for the rare ambiguous case (return to the Bands list) rather than guessing. This is a real API-contract gap worth flagging to the backend team, not a client bug.
