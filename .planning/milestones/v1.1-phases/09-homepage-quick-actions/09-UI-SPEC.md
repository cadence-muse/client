### 3. Quick-Action Button Row (D-02, D-10)

**Purpose:** Three buttons for Add Band, Add Song, Add Setlist — always visible regardless of band count.

**Button Properties:**

| Button | Icon | Label | State | Behavior |
|--------|------|-------|-------|----------|
| 1 | `Icons.group_add` (or similar) | "Add Band" | Always enabled | Tap → `Navigator.push(CreateBandScreen)` |
| 2 | `Icons.music_note` (or similar) | "Add Song" | Enabled if `bandsCount > 0`; disabled if `bandsCount == 0` | Tap → show band-picker bottom sheet → `Navigator.push(CreateTrackScreen(bandId: ...))` |
| 3 | `Icons.playlist_add` (or similar) | "Add Setlist" | Enabled if `bandsCount > 0`; disabled if `bandsCount == 0` | Tap → show band-picker bottom sheet → `Navigator.push(CreateSetlistScreen(bandId: ...))` |

**Widget Choice:** `ElevatedButton.icon`, `OutlinedButton.icon`, or `FilledButton.icon` — executor decides based on visual hierarchy and consistency with app's existing buttons (see create_band_screen.dart's `ElevatedButton` pattern). Recommend `ElevatedButton.icon` for consistency.

**Layout:**
- On wide screens (e.g., tablet): 3 buttons in a single row, equal width, separated by 16px (md) gaps. Use `Row` with `MainAxisAlignment.spaceEvenly` or `Expanded` children.
- On narrow screens (mobile): 3 buttons in a row that may wrap or stack. Options:
  - `Wrap` widget with `spacing: 16px` and `runSpacing: 8px` (buttons wrap naturally)
  - Fixed 3-per-row with smaller padding (buttons stay in one row on typical mobile widths)
  - Executor's choice based on visual testing. Minimum recommendation: buttons stay readable, tappable (48px+ height per Material guidelines).

**Icon + Label Styling:**
- Icon: 24dp (Material default)
- Label: 16px body text (`bodyMedium` or `bodyLarge`)
- Icon-to-label gap: 8px (Material standard for icon buttons)
- Padding: 16px horizontal, 12px vertical (Material standard for elevated buttons)

**Disabled State (Add Song / Add Setlist when `bandsCount == 0`):**
- Visual: Grayed-out text and icon (Material's default disabled color)
- Interaction: `onPressed: null` (disables tap and shows disabled cursor)
- No tooltip, snackbar, or explanatory text required per D-09 (disabled state itself communicates)

### 4. Band-Picker Bottom Sheet (D-05, D-06, D-07, D-08)

**Purpose:** List bands for user to select when creating a song or setlist.

**Trigger:**
- User taps "Add Song" or "Add Setlist" button
- `showModalBottomSheet<String>(context: context, builder: (sheetContext) => _buildBandPickerSheet(...))`

**Data Source:**
- `bandsListDataProvider` (existing Riverpod provider from bands_screen.dart)
- No new provider, no new API call
- Works offline (serves cached data, relies on global offline banner for staleness indicator)

**Sheet Structure:**
```
┌────────────────────────┐
│ Band 1                 │  ← ListTile(leading: Icon, title: Text(bandName), onTap: ...)
├────────────────────────┤
│ Band 2                 │
├────────────────────────┤
│ Band 3                 │
└────────────────────────┘
```

**Implementation Details:**
- Widget: `showModalBottomSheet` (Flutter standard)
- Content wrapper: `SafeArea` + `Column(mainAxisSize: MainAxisSize.min, ...)`
- List items: `ListTile` per band
  - `leading: Icon(Icons.music_note)` or `Icons.group` (band icon)
  - `title: Text(bandName)`
  - No subtitle, no trailing widget, no member count/role badge (lightweight per D-05)
  - `onTap: () { Navigator.of(sheetContext).pop(bandId); }` — returns selected bandId to parent context
- Scrolling: If band list exceeds sheet height, wrap `Column` in `ListView` or let Material handle scrolling automatically

**Band List Rendering:**
- Load data from `ref.watch(bandsListDataProvider)` in the parent screen's build method
- Pass `bandsAsync.value` (or empty list if loading/error) to picker
- If `bandsAsync.isLoading`: show spinner overlay or skip showing sheet (user stays on Home)
- If `bandsAsync.hasError`: show error state on Home; picker does not open

**On Selection:**
1. User taps a ListTile
2. `Navigator.of(sheetContext).pop()` closes the sheet
3. Callback in parent context receives selectedBandId
4. `Navigator.of(context).push(MaterialPageRoute(builder: (_) => CreateTrackScreen(bandId: selectedBandId)))` (or CreateSetlistScreen)

**On Dismiss (tap outside / back):**
- Sheet closes without selection
- No error, no snackbar
- User remains on Home per D-08

**Always Show:**
- Picker displays even with 1 band (no auto-skip per D-07)
- Same ListTile rendering logic for N=1, N=5, N=many

## Interaction Flow (Happy Path)

### Path 1: Add Band
```
Home Tab
  ↓ [tap "Add Band"]
  ↓ Navigator.push(CreateBandScreen)
  ↓ [user creates band]
  ↓ navigator.pushReplacement(BandDetailScreen)
  → User sees new band's detail
```

### Path 2: Add Song
```
Home Tab
  ↓ [tap "Add Song"]
  ↓ showModalBottomSheet(band picker)
  ↓ [user selects band]
  ↓ Navigator.of(context).pop() [closes sheet]
  ↓ Navigator.push(CreateTrackScreen(bandId: ...))
  ↓ [user creates track]
  ↓ Navigator.pushReplacement(TrackDetailScreen)
  → User sees new track's detail
```

### Path 3: Add Setlist
```
Home Tab
  ↓ [tap "Add Setlist"]
  ↓ showModalBottomSheet(band picker)
  ↓ [user selects band]
  ↓ Navigator.of(context).pop() [closes sheet]
  ↓ Navigator.push(CreateSetlistScreen(bandId: ...))
  ↓ [user creates setlist]
  ↓ Navigator.pushReplacement(SetlistDetailScreen)
  → User sees new setlist's detail
```

### Path 4: Dismiss Band Picker
```
Home Tab
  ↓ [tap "Add Song" or "Add Setlist"]
  ↓ showModalBottomSheet(band picker)
  ↓ [user taps outside or presses back]
  ↓ showModalBottomSheet closes
  → User remains on Home Tab
```

### Path 5: Add Song / Setlist Disabled (Zero Bands)
```
Home Tab (with bandsCount == 0)
  ↓ [tap "Add Song" → no response; button is disabled]
  ↓ OR [tap "Add Setlist" → no response; button is disabled]
  ↓ OR [tap "Add Band" → enabled, navigates to CreateBandScreen]
```
