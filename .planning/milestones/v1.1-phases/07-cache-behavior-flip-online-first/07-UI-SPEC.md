## Copywriting Contract

### Primary Banner: Offline State (D-04)

**Element:** `OfflineBanner` widget (global, `RootScaffold` level)

| Aspect | Specification |
|--------|---------------|
| **Copy** | `Showing cached data — may be out of date` |
| **Previous copy** (removed) | `You're offline — showing cached data` |
| **Rationale** | D-04: Reworded to be connectivity-agnostic — covers both true-offline and online-but-fetch-failed cases. Does not claim "you're offline" literally since silent fallback to cache can happen while device is technically online (connectivity_plus reports radio state, not active internet). |
| **Icon** | `Icons.cloud_off` (Material Icons) |
| **Colors** | `errorContainer` background + `onErrorContainer` text/icon |
| **Placement** | Top of `RootScaffold.body`, above `IndexedStack` (all 5 tab screens) |
| **Visibility** | Shown only when `isOnlineProvider` is false (device-level connectivity from `connectivity_plus`) |
| **Padding** | Horizontal 16px, vertical 8px (standard Material spacing) |
| **Duration** | Persistent (no auto-dismiss); visible for entire offline session |

**Layout example:**
```
┌────────────────────────────┐
│ 🌥️  Showing cached data — may be out of date │  ← OfflineBanner
├────────────────────────────┤
│                            │
│   IndexedStack (Home/     │
│   Bands/Tracks/Setlists/  │
│   Profile content)         │
│                            │
└────────────────────────────┘
```

### Secondary State: Offline + No-Cache Error (D-06, D-07)

**Element:** New error state in each tab screen's `AsyncValue.when()` error branch

| Aspect | Specification |
|--------|---------------|
| **Trigger condition** | Screen opened offline (`isOnlineProvider` false) AND no cache data exists for this screen's provider |
| **Exception type** | `OfflineNoCacheException` (custom exception in provider layer) |
| **Screen state** | Full-screen centered error layout (reusing existing `_buildError()` widget structure) |
| **Heading** | `No cached data` |
| **Body text** | `Connect to the internet to load this` |
| **Icon** | `Icons.cloud_off_outlined` (outlined variant, larger size 64px) |
| **Icon color** | `colorScheme.onSurfaceVariant` |
| **Retry button** | **None** — no retry possible while offline |
| **Recovery behavior** | Automatic (D-07) — screen listens to `isOnlineProvider`, and the instant it flips to online, it refetches automatically with no user action needed |

**Layout example:**
```
┌────────────────────────────┐
│ Showing cached data —      │  ← OfflineBanner
├────────────────────────────┤
│                            │
│           ☁️❌             │  ← cloud_off_outlined icon (64px)
│                            │
│     No cached data         │  ← heading (headlineSmall)
│                            │
│  Connect to the internet   │  ← body text (bodyMedium)
│  to load this              │
│                            │
└────────────────────────────┘
```

### Tertiary State: In-Flight Refresh Indicator (D-08, D-09)

**Element:** Subtle progress indicator in AppBar while refetching with cached data present

| Aspect | Specification |
|--------|---------------|
| **Trigger** | When provider's `AsyncValue.isLoading` is true AND `AsyncValue.hasValue` is true (refreshing with old data present) |
| **Indicator type** | `LinearProgressIndicator` (thin, indeterminate progress bar) |
| **Placement** | AppBar's `bottom` property (below title text, above screen content) |
| **Height** | 2px (thin, non-intrusive) |
| **Color** | `colorScheme.primary` (green, Material 3 default) |
| **Visibility timing** | Only shown during background refresh **after** first successful load (D-08). On cold start (no data yet), show full-screen `CircularProgressIndicator` centered in screen (D-09 exception). |
| **Duration** | Visible until fetch completes and new data arrives; automatic removal when state transitions to `AsyncData` |

**Screen state examples:**

**Cold start (D-09):**
```
┌────────────────────────────┐
│ Showing cached data —      │  ← OfflineBanner
├────────────────────────────┤
│                            │
│      ⟳ (spinner)           │  ← Full-screen centered CircularProgressIndicator
│                            │
│    Loading bands...        │  ← Implicit message (or none, per Material)
│                            │
└────────────────────────────┘
```

**Refresh with cached data present (D-08):**
```
┌────────────────────────────┐
│ Showing cached data —      │
├────────────────────────────┤
│ Bands                    ⋮ │  ← AppBar title
│ ══════════════════════════ │  ← LinearProgressIndicator (2px, thin)
│                            │
│ • Band A                   │  ← Old cached band list still visible
│ • Band B                   │
│ • Band C                   │
│                            │
└────────────────────────────┘
```

## UI Considerations

Post-verification state-coverage probe (ui-consideration-probe engine, run after checker approval): **17 resolved (10 explicit, 7 backstop), 1 unclassified — 18 applicable**

### E1 — OfflineBanner

| Category | Status | Truth |
|----------|--------|-------|
| Empty | ✅ resolved (explicit) | No empty-data state — always renders the fixed cloud_off icon + "Showing cached data — may be out of date" text whenever `isOnlineProvider` is false; no underlying collection can be empty. |
| Loading | ✅ resolved (explicit) | Not loading-dependent — renders instantly from `isOnlineProvider`'s synchronous value; no skeleton/loading state for the banner itself. |
| Error | ✅ resolved (explicit) | No error state of its own — connectivity_plus stream failures are not surfaced through the banner; it only reflects the boolean `isOnlineProvider` value. |
| Populated | ✅ resolved (explicit) | The single populated state is the row already specified in the Copywriting Contract (cloud_off icon + banner text, errorContainer background, top of `RootScaffold.body`). |
| Overflow | ⚠ resolved (backstop) | Fixed short string fits one line under Material defaults on all supported widths — needs a visual check on the smallest supported screen width. |
| Long-text | ⚠ resolved (backstop) | Fixed, non-localized string authored to fit one line; Material `Text` wraps by default if a future localized translation is longer — needs verification once localization is added. |

### E2 — Offline-no-cache error state

| Category | Status | Truth |
|----------|--------|-------|
| Loading | ✅ resolved (explicit) | No loading sub-state — this branch renders only after offline+no-cache is already known; no async fetch inside it. |
| Error | ✅ resolved (explicit) | This element IS the terminal error/empty state: heading "No cached data", body "Connect to the internet to load this", `cloud_off_outlined` icon, no retry button, automatic recovery on reconnect. |
| Overflow | ⚠ resolved (backstop) | Short, center-aligned body copy under Material defaults — needs a visual check on the smallest supported screen width. |
| Long-text | ⚠ resolved (backstop) | Fixed short strings; wrapping falls to Material `Text` default wrap — needs verification if a localized string is longer. |

### E3 — In-flight refresh indicator

| Category | Status | Truth |
|----------|--------|-------|
| Empty | ✅ resolved (explicit) | Not applicable to the indicator itself — visibility is driven by `AsyncValue.isLoading`, not by whether the underlying list is empty; an empty list can still show the `LinearProgressIndicator` while refreshing. |
| Loading | ✅ resolved (explicit) | This element IS the loading-state contract: `LinearProgressIndicator` in `AppBar.bottom` when `isLoading && hasValue` (refresh), full-screen `CircularProgressIndicator` when `isLoading && !hasValue` (cold start). |
| Error | ✅ resolved (explicit) | If refresh fails, `AsyncValue` moves to `AsyncError` while cached content stays visible (D-03 silent fallback to cache) — indicator disappears with no separate error UI drawn over stale content. |
| Populated | ✅ resolved (explicit) | Populated state during refresh is the pre-existing screen content (e.g. old cached band list) rendered underneath the thin progress bar, per the "Refresh with cached data present" layout example. |
| Partial | ⚠ resolved (backstop) | Partial/incomplete row data during a refresh is governed by each screen's own list-item rendering, not this indicator — needs verification per screen's data model (outside Phase 7 scope). |
| Overflow | ⚠ resolved (backstop) | Fixed 2px bar spanning the full AppBar width — no text-overflow surface applies. |
| Zero-one-many | ⚠ resolved (backstop) | Indicator behavior is identical regardless of underlying item count — it only reflects loading state, not row count; needs a quick visual check against an empty cached list. |

### E4 — SyncStatusBadge removal

| Category | Status | Truth |
|----------|--------|-------|
| Unclassified | ⚠ unresolved — planner must treat as assumption | A pure deletion (10 call-sites, no replacement widget) isn't a stateful UI surface, so the probe found no state cues to classify — manual-review nudge only, not a defect. Removal scope is fully specified in the "Removed: SyncStatusBadge" section above. |

## Phase-Specific Notes

### What This Phase Changes (UI Layer)

1. **OfflineBanner text:** Reword from "You're offline — showing cached data" to "Showing cached data — may be out of date" (D-04)
2. **SyncStatusBadge removal:** Delete widget and all 10 instantiations
3. **Offline-no-cache error state:** Add new `OfflineNoCacheException` branch to error handling in all screens
4. **In-flight refresh indicator:** Add subtle `LinearProgressIndicator` to AppBar when refetching with data present (D-08)

### What This Phase Does NOT Change (Non-UI)

- Data layer provider logic (cache-first → online-first inversion) — spec'd in RESEARCH.md, implemented in provider layer
- Navigation structure or routing
- Authentication or token handling
- API contract or HTTP client
- Screen layout or component tree structure
- App theme (colors, fonts, spacing scale)

### Integration Points

- **OfflineBanner:** Already exists in `RootScaffold`; only text needs update
- **SyncStatusBadge:** Already exists in 10 screens; needs complete removal
- **Tab-screen refetch trigger (D-01):** Wired in provider layer (not UI layer) via `selectedTabIndexProvider` listener
- **In-flight indicator:** Rendered in each screen's AppBar conditionally based on provider's `AsyncValue.isLoading && hasValue`
- **Offline-no-cache state:** Handled in each screen's error branch, throwing/catching `OfflineNoCacheException`
