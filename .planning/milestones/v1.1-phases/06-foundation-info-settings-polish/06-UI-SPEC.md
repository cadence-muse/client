|------|-------|-------|

- Primary action buttons (Save, Change Password, Add, Create)

## UI Components & Patterns

### Password Change Form

**Location:** Profile screen (`lib/features/profile/profile_screen.dart`)

**Visual Hierarchy:**
- Focal point: full-width submit button (`FilledButton` in accent color)
- Visual flow: form title (larger, bold) → stacked inputs (secondary prominence) → submit button (primary action)
- Form title uses `textTheme.headlineMedium` (28px, 400 weight)
- Input fields use `textTheme.bodyMedium` labels (14px, 400 weight)

**Layout:**
- Three TextFormField inputs stacked vertically
- 16px spacing between fields (`const SizedBox(height: 16)`)
- Each field uses `OutlineInputBorder()` (matches existing LoginScreen pattern)
- Submit button: `FilledButton` spanning full width (matches LoginScreen pattern), colored with `colorScheme.primary` (green)
- Disabled while submitting (loading spinner on button)

**Fields:**
1. Current password (label: "Current password", obscureText: true, required)
2. New password (label: "New password", obscureText: true, required, min 8 chars)
3. Confirm new password (label: "Confirm new password", obscureText: true, required, must match new password)

**Validators:**
- Current password: required (non-empty)
- New password: required, min 8 characters
- Confirm password: required, must match new password exactly

**Success Feedback:**
- On successful change, show SnackBar: "Password changed successfully"
- Remain on Profile screen (no navigation)

**Error Handling:**
- Server returns 401 → "Current password is incorrect" (displayed as red text below form)
- Validation failures → field-level error messages displayed inline
- Network error → "An error occurred. Please try again."

**State:**
- Initially: all fields empty, button enabled
- While submitting: button disabled, loading spinner
- After success: fields cleared, SnackBar shown
- On error: red text displayed below the form, fields preserved (user can retry)

### Band Member Count & Role Display

**Location:** 
- `lib/features/bands/bands_screen.dart` (list view)
- `lib/features/bands/band_detail_screen.dart` (detail view)

**List View Pattern:**
- ListTile with `trailing` widget containing: `"{count} member{s}" • "Owner"` or `"{count} member{s}" • "Member"`
- Icon before role label: optional role badge (visual indicator)
- Example: `"3 members • Owner"` or `"5 members • Member"`
- Font: `textTheme.bodySmall` or `textTheme.labelMedium` in trailing area
- Spacing: single line, compact

**Detail Screen Pattern:**
- Display below band name/avatar
- Layout: role badge on left, member count on right (two-column grid or single row)
- Example row: `👑 Owner  •  3 members`
- Icon choices (visual only, not clickable):
  - Owner: `Icons.star` (gold/yellow accent color) or no icon, just text
  - Member: no icon, plain text

**Implementation Notes:**
- Role computed via existing helper `_isOwner(currentUserId, ownerId)` in band_detail_screen.dart
- Reuse for list screen without reimplementing
- Member count comes from `BandListItem.membersCount` (already present in v1.0 API)
- Owner ID comes from new `BandListItem.ownerId` field (added in Phase 6 spec)

### Track List Metadata Icons

**Location:** `lib/features/tracks/track_list_screen.dart` and `track_detail_screen.dart`

**Icon Row Style (List Screen):**
- Displayed in ListTile `trailing` area as horizontal row
- Format: `[Icon] value  [Icon] value  [Icon] value` (if all fields present)
- Spacing between icon-value pairs: 8px (`const SizedBox(width: 8)`)
- Spacing between icon and text: 4px
- Font: `textTheme.labelSmall` or `bodySmall` for conciseness
- Icons: `Icons.music_note` (key), `Icons.timer` (duration), `Icons.notes` (notes)

**Fields:**
1. **Key** (optional) — shown only if `TrackListItem.key` is present
   - Icon: `Icons.music_note` (color: `colorScheme.primary`)
   - Value: `"{key}"` (e.g., "C" or "Cm" from the musicKeys list)
   
2. **Duration** (always shown)
   - Icon: `Icons.timer` (color: `colorScheme.primary`)
   - Value: formatted via `DurationFormatting.asMinutesSeconds` (e.g., "3:45")
   
3. **Notes** (detail screen only, not in list)
   - Icon: `Icons.notes` (color: `colorScheme.primary`)
   - Shown only on track detail screen as a section header or inline

**Graceful Degradation:**
- If `key` field is missing/null from server, omit the music_note icon and value
- If `notes` field is missing/null, omit the notes section (never show placeholder text like "No notes")
- Duration always present (required field in schema)

**Example List Row:**
```
Track Title (title)        🎵 C   ⏱ 3:45
```

### Setlist List Metadata Icons

**Location:** `lib/features/setlists/setlist_list_screen.dart` and `setlist_detail_screen.dart`

**Icon Row Style (List Screen):**
- Same as Track list (horizontal row in `trailing` area)
- Spacing between icon-value pairs: 8px
- Spacing between icon and text: 4px
- Font: `textTheme.labelSmall` or `bodySmall`
- Icons: `Icons.location_on` (location), `Icons.timer` (duration)

**Fields:**
1. **Location** (optional) — shown only if `SetlistListItem.eventLocation` is present
   - Icon: `Icons.location_on` (color: `colorScheme.primary`)
   - Value: `"{eventLocation}"` (e.g., "Whisky Barrel" or "The Fillmore")
   
2. **Duration** (always shown)
   - Icon: `Icons.timer` (color: `colorScheme.primary`)
   - Value: calculated from sum of all track durations in the setlist (e.g., "45:30")
   - Use `DurationFormatting.asMinutesSeconds` for consistent formatting

**Graceful Degradation:**
- If `eventLocation` field is missing/null from server, omit the location_on icon and value
- Duration always calculated (derived from existing track data)

**Example List Row:**
```
Tonight's Show (title)     📍 The Fillmore   ⏱ 45:30
```

## Form Validation Rules

### Password Change Form

| Field | Rules |
|-------|-------|
| Current password | Required (non-empty). No length minimum (user may have set any password). Error: "This field is required" (generic validator). |
| New password | Required, min 8 characters (matches auth requirements). Error: "At least 8 characters". |
| Confirm new password | Required, must match "New password" field exactly. Error: "Passwords don't match". |
| Overall form | Submit only if all fields pass validation and not already submitting. |

**API Integration:**
- After validation passes, call `PublicApi.changePassword(currentPassword: ..., newPassword: ...)`
- Server may return 401 if currentPassword is incorrect → display "Current password is incorrect"
- Server may accept the request successfully → show SnackBar and clear form
