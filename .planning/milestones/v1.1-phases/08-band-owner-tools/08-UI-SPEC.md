## Color

Material 3 ColorScheme (green seed):

| Role | Light Mode | Dark Mode | Usage |
|------|-----------|-----------|-------|
| Dominant (surface) | White (#FFFFFF) | ~#121212 | App background, ListTile backgrounds |
| Secondary (cards, nav) | ~#F5F5F5 | ~#1E1E1E | Section backgrounds, dividers |
| Primary (accent) | ~#2E7D32 (green) | ~#81C784 (green) | Interactive elements, checkmarks |
| Error (destructive) | ~#B3261E | ~#F9DEDC | Delete/Remove actions, error text |

**Accent reserved for:**
- Owner-gated controls (Make owner icon, Rotate icon, Transfer/Rotate dialogs)
- Primary CTA buttons (Confirm dialogs)
- No accent on info-only displays

**Destructive actions:**
- Remove member: error color (red) + `Icons.person_remove`
- Delete band: error color (red) + `Icons.delete`
- Not destructive: Transfer (ownership stays in band), Rotate (code regeneration is reversible)

**Application this phase:**
- "Make owner" menu item icon: Use primary color (non-destructive signal)
- "Remove" menu item icon: Keep error color (red, destructive signal)
- Rotate invite code button: Use primary color (non-destructive)
- Transfer ownership dialog: Use primary/error colors per action semantics (button is primary, since action succeeds if confirmed)

## UI Components & Patterns

### 1. Member List Row Modifications

**Current State (Phase 7):**
```
ListTile(
  title: Text(memberUsername),
  trailing: IconButton(person_remove, onPressed: _showRemoveDialog)
)
```

**New State (Phase 8):**
```
ListTile(
  title: Text(memberUsername),
  trailing: Tooltip(
    message: isOnline ? '' : 'Requires connection',
    child: PopupMenuButton(
      enabled: isOnline,
      itemBuilder: (_) => [
        PopupMenuItem(
          child: Row(
            mainAxisSize: MainAxisSize.min,
            children: [
              Icon(Icons.workspace_premium), // crown-like icon
              SizedBox(width: 8),
              Text('Make owner'),
            ],
          ),
          onTap: () => showDialog(ConfirmTransferOwnershipDialog(...))
        ),
        PopupMenuDivider(),
        PopupMenuItem(
          child: Row(
            mainAxisSize: MainAxisSize.min,
            children: [
              Icon(Icons.person_remove, color: error), // red
              SizedBox(width: 8),
              Text('Remove', style: TextStyle(color: error)),
            ],
          ),
          onTap: () => showDialog(ConfirmRemoveMemberDialog(...))
        ),
      ],
    ),
  ),
)
```

**Interaction Rules:**
- PopupMenuButton visible only when `isOwner == true`
- PopupMenuButton disabled (greyed out) when `!isOnline`
- Tooltip shows "Requires connection" when offline
- "Make owner" action hidden for the owner's own row (never shown when `memberUserId == ownerId`)
- "Remove" action same as today — never shown on owner's row

**Styling:**
- Menu items use Material defaults
- "Make owner" icon: `Icons.workspace_premium` (primary color)
- "Remove" icon: `Icons.person_remove` (error/red color)

### 2. Invite Code Row Modifications

**Current State (Phase 7):**
```
Row(
  children: [
    Expanded(child: Text(inviteCode, fontFamily: 'monospace')),
    TextButton(
      onPressed: () => _copyInviteCode(...),
      child: Text('Copy'),
    ),
  ],

```

**New State (Phase 8):**
```
Row(
  children: [
    Expanded(child: Text(inviteCode, fontFamily: 'monospace')),
    Tooltip(
      message: isOnline ? 'Copy' : '',
      child: IconButton(
        icon: Icon(Icons.content_copy),
        onPressed: isOnline ? () => _copyInviteCode(...) : null,
      ),
    ),
    if (isOwner == true)
      Tooltip(
        message: isOnline ? 'Rotate' : 'Requires connection',
        child: IconButton(
          icon: Icon(Icons.refresh), // or Icons.autorenew
          onPressed: isOnline ? () => showDialog(ConfirmRotateInviteCodeDialog(...)) : null,
        ),
      ),
  ],
)
```

**Interaction Rules:**
- Copy icon always visible, disabled when `!isOnline`
- Rotate icon visible only when `isOwner == true`, disabled when `!isOnline`
- Both IconButtons use Tooltip for affordance
- Rotate icon: `Icons.refresh` or `Icons.autorenew` (circular-arrow style, primary color)
- Copy icon: `Icons.content_copy` (primary color)

**Styling:**
- Both icons inherit primary color from theme
- Both disabled state: greyed out + tooltip "Requires connection"

### 3. ConfirmTransferOwnershipDialog

**Template:** Based on `ConfirmRemoveMemberDialog` (exact pattern reused).

**Location:** `lib/features/bands/confirm_transfer_ownership_dialog.dart` (new file).

**Layout:**
```
AlertDialog(
  title: Text('Transfer ownership to $memberUsername?'),
  content: Column(
    mainAxisSize: MainAxisSize.min,
    crossAxisAlignment: CrossAxisAlignment.start,
    children: [
      Text(
        '$memberUsername will become the owner of this band.\n\n'
        'You will no longer be the owner of $bandName.',
      ),
      if (_errorMessage != null) ...[
        SizedBox(height: 16),
        Text(
          _errorMessage!,
          style: TextStyle(color: Theme.of(context).colorScheme.error),
        ),
      ],
    ],
  ),
  actions: [
    TextButton(
      onPressed: () => Navigator.of(context).pop(),
      child: Text('Cancel'),
    ),
    Tooltip(
      message: isOnline ? '' : 'Requires connection',
      child: FilledButton(
        onPressed: (!isOnline || _isSubmitting) ? null : _transfer,
        child: _isSubmitting
            ? SizedBox(
                height: 20,
                width: 20,
                child: CircularProgressIndicator(strokeWidth: 2),
              )
            : Text('Transfer'),
      ),
    ),
  ],
)
```

**Copy Requirements (D-04):**
- Title: "Transfer ownership to [member name]?"
- Body: MUST state the self-effect explicitly — "You will no longer be the owner of [band name]"
- Button: "Transfer" (primary action)
- Cancel: "Cancel"

**State Management:**
- `_isSubmitting`: Boolean flag for loading state
- `_errorMessage`: Nullable string for API error display
- Error text styling: `color: Theme.of(context).colorScheme.error`

**Interaction Rules (D-05):**
- Loading spinner in confirm button when submitting
- Dialog stays open on API error
- Error message displayed inline below body text
- Confirm button disabled when `!isOnline` (Tooltip: "Requires connection")
- Confirm button disabled during submission
- Pop dialog only on success + dependency invalidation

**API Integration:**
- Call: `ref.read(publicApiProvider).transferOwnership(bandId: bandId, userId: memberUserId)`
- On success:
  1. `ref.invalidate(bandDetailDataProvider(bandId))` — refetch detail screen (D-09)
  2. `ref.read(bandsListDataProvider).patchBandOwner(bandId, userId)` — patch list entry (D-10)
  3. `Navigator.of(context).pop()` — close dialog
  4. Show snackbar: "Ownership transferred" (optional, but recommended)
- On error: Set `_errorMessage`, stay open

## UI Considerations

Domain/offline coverage (below) is prose-owned per phase decisions D-01–D-12. Shape-rooted state
coverage (loading/error/overflow/long-text) was verified via the UI-consideration probe against four
elements: **E1** member action menu (PopupMenuButton), **E2** invite code row (Copy/Rotate icons),
**E3** ConfirmTransferOwnershipDialog, **E4** ConfirmRotateInviteCodeDialog. Copy for empty/error
states lives in [Copywriting Contract](#copywriting-contract); rows below reference it rather than
restate it.

| Category | Element(s) | Status | Resolution |
|----------|----------|--------|-----------|
| Owner gating | Member list "Make owner" + Rotate icon | ✅ covered | Visible/enabled only when `isOwner == true` and profile loaded; tri-state ownership check reuses `BandDetailScreen.ownershipStatus()` |
| Offline gating | All owner controls + Copy icon | ✅ covered | All disabled when `!isOnline`; Tooltips show "Requires connection"; dialogs show same message on confirm button |
| Self-row edge case | "Make owner" + "Remove" on owner's own row | ✅ covered | Never shown; member-list rendering skips "Make owner"/"Remove" when `memberUserId == ownerId` |
| Error state (E3, E4) | Transfer/Rotate dialogs | ✅ resolved (explicit) | `_errorMessage` displayed inline in error color below body text; dialog stays open; button re-enabled for retry |
| Loading state (E3, E4) | Transfer/Rotate dialogs, confirm button | ✅ resolved (explicit) | `CircularProgressIndicator(strokeWidth: 2)` replaces button text; button disabled while `_isSubmitting` |
| Success feedback | After rotate/transfer | ✅ covered | Snackbar shown; dialog closes; screen re-renders with updated state (via invalidate/patch) |
| Code display | Invite code monospace rendering | ✅ covered | Uses `fontFamily: 'monospace'` (existing pattern) |
| Menu styling | PopupMenuButton internal structure | ✅ covered | Material defaults; icons + text labels per item; divider between Make/Remove |
| Empty response body | TransferBandOwnership returns 200 with no body | ✅ covered | No response parsing; invalidate detail + patch list via known `userId` (D-09/D-10) |
| Menu loading (E1) | Member action menu | ✅ resolved (explicit) | Menu (and its trigger) hidden entirely while ownership tri-state is `null` (profile still loading); no optimistic render-then-hide |
| Menu error (E1) | Member action menu | ✅ resolved (explicit) | The menu makes no network call and has no error state of its own; each item opens a dialog (E3/E4) that owns its own error handling |
| Menu overflow (E1) | Member action menu | ✅ resolved (backstop) | { statement: "Fixed 2-item menu with short static Material-default labels; PopupMenuButton auto-sizes to content.", verification: backstop — widget test asserting unclipped render at default text scale } |
| Menu long-text (E1) | Member action menu | ✅ resolved (backstop) | { statement: "Labels ('Make owner', 'Remove') are fixed app strings, never user-generated.", verification: backstop — widget test asserting unclipped render at max OS text-scale } |
| Invite row loading (E2) | Copy/Rotate icon row | ✅ resolved (explicit) | Row only renders once `BandDetailData` has loaded; the screen's own loading state (Phase 6) precedes it, unchanged by Phase 8 |
| Copy error (E2) | Copy icon | ⊘ dismissed | Reason: `Clipboard.setData` is a synchronous local platform call with no meaningful failure path on Android/iOS; no error UI needed for Copy |

| Invite code long-text (E2) | Invite code display | ⊘ dismissed | Reason: Invite code is fixed-length and backend-generated, never user-authored free text — no long-text scenario is possible |
| Dialog overflow (E3) | ConfirmTransferOwnershipDialog | ✅ resolved (backstop) | { statement: "Body Column uses mainAxisSize.min inside default AlertDialog sizing.", verification: backstop — widget test with a long member/band name asserting unclipped render } |
| Dialog long-text (E3) | ConfirmTransferOwnershipDialog | ✅ resolved (backstop) | { statement: "Title/body interpolate memberUsername and bandName; Text widgets wrap by default. No app-wide max-length is defined in this UI-SPEC.", verification: backstop — widget test with a long name asserting text wraps rather than clips } |

## Interaction Model

### Rotate Invite Code Flow

1. User (owner) taps Rotate icon on Invite Code row
2. ConfirmRotateInviteCodeDialog appears (modal)
3. User reads warning + taps "Rotate" or "Cancel"
4. If "Cancel" → dialog closes, no change
5. If "Rotate" → button shows spinner, icon button disabled
6. API call: `POST /api/band/{bandId}/rotate-invite-code`
7. On success:
   - Response: `{ newInviteCode: "..." }`
   - Optimistic local patch: `inviteCode` field updated in `BandDetailData`
   - Snackbar: "Invite code rotated"
   - Dialog closes
   - Invite code row re-renders with new code immediately visible
8. On error:
   - Error message shown in dialog (red text below body)
   - Button re-enabled
   - Dialog stays open

### Transfer Ownership Flow

1. User (owner) taps a non-owner member's row in member list
2. PopupMenuButton appears with "Make owner" + "Remove" items
3. User taps "Make owner"
4. ConfirmTransferOwnershipDialog appears (modal)
5. User reads confirmation + taps "Transfer" or "Cancel"
6. If "Cancel" → dialog closes, no change
7. If "Transfer" → button shows spinner, popup closed
8. API call: `POST /api/band/{bandId}/transfer-ownership` (body: `{ userId: "..." }`)
9. On success:
   - Response: empty (200 OK)
   - Invalidate `bandDetailDataProvider(bandId)` → triggers refetch (D-09)
   - Patch `bandsListDataProvider` → update ownerId for this band entry (D-10)
   - Snackbar: "Ownership transferred"
   - Dialog closes
   - Detail screen re-renders once refetch completes
   - Member list shows owner/member roles updated
   - "Make owner" icon now hidden for the new owner's row; visible for old owner's row
10. On error:
    - Error message shown in dialog (red text below body)
    - Button re-enabled
    - Dialog stays open

## Edge Cases & Constraints

| Case | Behavior |
|------|----------|
| User is offline when tapping owner control | All owner controls disabled; tooltip "Requires connection"; dialogs show same message |
| API request fails mid-flight | Error message displayed; dialog stays open; user can retry |
| Profile data still loading | Owner-gated controls hidden (tri-state ownership: `null`); no optimistic render-then-hide |
| User transfers ownership to member X, then taps back to Bands list without tab-switch | List patch ensures X's badge updates immediately; no stale "Owner" badge |
| User rotates code while looking at Bands list | No list update needed (Bands list doesn't display invite code) |
| User is the only owner | All controls available; can transfer to any other member |
| Transfer to self attempted (edge case) | Dialog won't be shown for owner's own row; not a concern |
