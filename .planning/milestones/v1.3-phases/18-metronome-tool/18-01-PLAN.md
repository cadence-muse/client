    choke point (D-06). `togglePlay()`: private fields `Timer? _checkTimer;
    Stopwatch? _stopwatch; int _nextTickDueMs = 0;`. If starting: `state =
    state.copyWith(isPlaying: true)`, `_stopwatch = Stopwatch()..start()`,
    `_nextTickDueMs = 0` (fires the first tick almost immediately),
    `_checkTimer = Timer.periodic(const Duration(milliseconds: 10), (_) =>
    _maybeTick())`. If stopping: `_checkTimer?.cancel()`, `_stopwatch?.stop()`, `state =
    state.copyWith(isPlaying: false)` (leave `currentBeat` as-is so a resumed play
    continues visually where it left off). `_maybeTick()`: read `state.bpm` FRESH on
    every call (never cache it) -- `final intervalMs = (60000 / state.bpm).round();`
    (NOT divided by 4 again: `bpm` already denotes quarter-note beats per minute in 4/4,

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User gesture -> BPM state | Dial drag / quick-adjust taps (Plan 18-02) and any future BPM-changing input funnel into `setBpm` -- untrusted only in the sense of arbitrary user input, not a network boundary. |
| Native audio plugin <-> Dart | `audioplayers`' platform channel can fail (missing asset, unsupported codec, platform quirk) -- failure must degrade gracefully, not crash or leak file-system detail to the user. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-01 | Tampering | MetronomeState.setBpm (lib/providers/metronome_provider.dart) | medium | mitigate | setBpm always applies .clamp(40, 300) before writing state -- the single choke point; no other code path writes `state` directly for bpm. |
| T-18-02 | Information Disclosure | MetronomeAudioService.initialize() / AudioPlayersTickSoundPlayer (lib/features/metronome/audio/) | low | mitigate | Asset-load failures are caught internally and reduce to a boolean `_assetsLoaded` flag; the user-facing error text is the fixed UI-SPEC copy ("Couldn't load metronome. Try again."), never the raw exception message or asset file path. |
| T-18-03 | Denial of Service | MetronomeState Timer loop | low | accept | BPM is clamped to [40,300] (min tick interval 200ms at 300 BPM), bounding resource use; Timer is cancelled on dispose/backgrounding (T-18-04). No unbounded loop possible. |
| T-18-04 | Denial of Service (battery/background) | MetronomeState Timer + audio playback | low | mitigate | AppLifecycleListener stops playback (cancels Timer, stops Stopwatch) on AppLifecycleState.paused/inactive/hidden, preventing the metronome from silently running in the background -- matches REQUIREMENTS.md's explicit out-of-scope boundary for background audio. |
