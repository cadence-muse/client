<objective>
Fix `LoginScreen`'s shared password field validator so the `length < 8` check only applies in sign-up mode (D-04). Today it applies to both modes, which client-side-blocks a *login* attempt for any pre-existing user whose password was valid before the 8-char minimum existed — a bug fix, not new validation (API-02; `ChangePasswordScreen`'s equivalent validator is already correct and untouched, D-05).

Purpose: Stop locking out legitimate existing users at the client before their login request ever reaches the server.
Output: `LoginScreen`'s password validator gates the length check on `_AuthMode.signUp`.
</objective>
