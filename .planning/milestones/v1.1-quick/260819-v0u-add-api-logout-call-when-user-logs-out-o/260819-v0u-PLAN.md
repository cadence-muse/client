title: Add POST /api/logout call on profile-screen sign-out
description: >
  Wire the new POST /api/logout endpoint (already added to lib/api/publicapi.yml)
  into AuthSession.signOut() as a best-effort call, so the backend session is
  invalidated when the user logs out from the Profile screen, without blocking
  or breaking local sign-out when offline or on any backend error.
files_modified:
  - lib/api/public_api.dart
  - lib/providers/auth_provider.dart
  - test/providers/auth_provider_test.dart
---

<objective>
On logout from the Profile screen, call the backend `POST /api/logout` endpoint
(per `lib/api/publicapi.yml`'s `Logout` operation) using the current session
token, in addition to the existing local token/cache clear. The backend call
must be best-effort: local sign-out (drop token, clear cache, flip auth state)
must always succeed even if the network call fails or the device is offline —
this milestone has no offline mutation queue, so this is a fire-and-forget call,
not a queued mutation.
</objective>

<task type="auto" tdd="true">
  <name>Task 2: Call logout best-effort from AuthSession.signOut()</name>
  <files>lib/providers/auth_provider.dart</files>
  <behavior>
    - `signOut()` still clears the token via `TokenStorage.delete()`, clears
      the cache via `CacheService.clearAll()`, and sets state to
      `AsyncData(null)` — unchanged from today.
    - `signOut()` additionally calls `publicApiProvider`'s `logout()` using
      the token that was active when signOut() was invoked (the call must
      fire while the token is still attached — i.e. before local state is
      cleared — since `ApiClient`'s `getToken` callback reads
      `authSessionProvider`'s current value).
    - If the `logout()` call throws for any reason (network error, timeout,
      offline, `ApiException` from any status code including 403), the local
      sign-out steps still complete exactly once — the error must not
      propagate out of `signOut()` and must not stop the local clear.
    - `ApiClient.onUnauthorized` is wired to
      `authSessionProvider.notifier.signOut()`. Since the logout call itself
      can legitimately 403 (e.g. an already-expired token), `send()`'s 403
      handling calls `onUnauthorized()` — i.e. `signOut()` — from *inside*
      the in-flight `logout()` call, before that call throws. Without a
      reentrancy guard this nested call sees `state.value` still non-null
      and would itself call `logout()` again, repeating the same 403 and
      recursing without a depth bound. Add an instance-level boolean guard
      (e.g. `_loggingOut`) on the `AuthSession` notifier that is checked
      alongside the existing `state.value == null` early return, set `true`
      before the `logout()` attempt, and reset in a `finally` — so a nested
      call triggered from inside the outer call's own `logout()` returns
      immediately instead of re-attempting the network call, and the outer
      call performs the local clear exactly once after its `try`/`catch`
      completes.
  </behavior>
  <action>
    In `lib/providers/auth_provider.dart`, add a private `bool _loggingOut = false;`
    field to the `AuthSession` class. Update `signOut()`: keep the existing
    `if (state.value == null) return;` guard but extend it to also return
    early when `_loggingOut` is true. After that guard, set `_loggingOut = true`,
    wrap `await ref.read(publicApiProvider).logout();` in
    `try { ... } catch (_) { }` (swallow all errors — comment explaining this
    is best-effort per the milestone's no-offline-mutation-queue scope), then
    in a `finally` block set `_loggingOut = false`. After the try/finally,
    perform the existing local-clear sequence (`tokenStorage.delete()`,
    `cacheService.clearAll()`, `state = const AsyncData(null)`) exactly as
    today, unchanged, so it always runs regardless of the network outcome.
  </action>
  <verify>
    <automated>flutter test test/providers/auth_provider_test.dart</automated>
  </verify>
  <done>signOut() attempts POST /api/logout with the active token before clearing local state; local token/cache clear always completes even when the backend call throws; a 403 on the logout call itself does not cause unbounded recursion through onUnauthorized.</done>
</task>
