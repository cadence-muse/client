<objective>
Establish the complete ARB key set for the entire phase in one batch (all ~130 keys across every domain — bands, home, profile, setlists, tracks, nav, offline widgets, login), then prove the full localization pipeline end-to-end on the Bands tab and Band Detail screen: ARB -> gen-l10n codegen -> `AppLocalizations.of(context)!.key` in a screen -> `tester.strings.key` in that screen's test.

This plan is Wave 1 and every other plan in this phase depends on it. Batching every ARB key here — including keys consumed only by later plans (setlists, tracks, profile, etc.) — is a deliberate architectural decision: `app_en.arb`/`app_ru.arb` are the one shared resource every downstream plan reads from. If per-domain plans each added their own keys to these two files, every one of those plans would conflict on the same files and be forced fully sequential, destroying the wave-based parallelism this phase's plan set depends on. Front-loading the full key list here lets all 10 Wave-2 plans run in parallel, touching only their own screen/dialog/test files.

Purpose: Prove the ARB/gen-l10n/AppLocalizations/tester.strings pipeline (already proven for simple strings in Phase 12) also works correctly for ICU plurals and placeholders — the two patterns this phase introduces for the first time — before 10 parallel plans build on it. Establishes `_membersLabel`'s replacement (`memberCount()`) and the D-09/D-10 role-label split as the canonical pattern for every other "N of something" count string in the app.

Output: Complete `app_en.arb`/`app_ru.arb` (~130 keys, all ICU plural/placeholder syntax verified via `flutter pub run build_runner build`), `test/test_strings.dart` WidgetTester extension, fully localized `bands_screen.dart` + `band_detail_screen.dart` with passing tests.
</objective>
