# Quick Task 260828-c98: 401 Auto-Logout + Session-Expired Toast Summary

**A 401 from any authenticated API call now triggers the same auto-logout path as a 403, and `LoginScreen` shows a one-time "Session expired" SnackBar exactly on that forced sign-out -- never on manual logout or cold start.**

## Performance

- **Duration:** 35 min
- **Started:** 2026-08-28T00:00:00Z (approx.)
- **Completed:** 2026-08-28
- **Tasks:** 3
- **Files modified:** 10 (1 created, 9 modified)

## Accomplishments
- `ApiClient.send()` now calls `onUnauthorized()` for both `401` and `403` responses (previously only `403`); `400`/`200` behavior unchanged.
- `AuthSession.signOut()` gained an optional `sessionExpired` named bool (default `false`) and a new `consumeSessionExpired()` one-time-read accessor; `apiClientProvider`'s `onUnauthorized` now passes `sessionExpired: true`.
- `LoginScreen.initState()` consumes that flag and shows a post-frame `SnackBar` reading the new `loginSessionExpiredSnackbar` ARB string ("Session expired" / "Сессия истекла") exactly when the prior sign-out was forced.

## Decisions Made
- Reused the exact same `403`-handling branch condition for `401` rather than a parallel code path (both are middleware-level auth failures, outside the OpenAPI per-operation contract).
- `sessionExpired` defaults to `false` on `signOut()` so the Profile screen's manual "Log out" (`signOut()` with no args) keeps behaving identically -- no toast.
- `consumeSessionExpired()` resets the flag on read (one-time consumption) so a later rebuild of `LoginScreen` never re-shows the toast.
